## 2. Что такое процесс

**Процесс** — это программа в момент выполнения. У каждого процесса есть:

- **PID** — уникальный идентификатор.
- **PPID** — идентификатор родителя.
- **Своё адресное пространство** — память.
- **Открытые дескрипторы** — файлы, сокеты, каналы.
- **Состояние** — running, sleeping, zombie, stopped.

Процессы образуют **дерево**: у каждого есть родитель (кроме `init` с PID 1).

**Как узнать свой PID:**

```c
#include <unistd.h>

pid_t pid = getpid();     // свой PID
pid_t ppid = getppid();   // PID родителя
```

## 3. `fork` — создание процесса

```c
#include <unistd.h>

pid_t fork(void);
```

**Что делает:** создаёт **копию** текущего процесса. Новый процесс называется **дочерним**, исходный — **родительским**.

**Возвращает:**

| Где | Что возвращает |
|-----|----------------|
| Родитель | PID ребёнка (> 0) |
| Ребёнок | 0 |
| Ошибка | -1 |

⚠️ **`fork` вызывается один раз, но возвращается дважды** — в родителе и в ребёнке. После вызова **оба процесса** продолжают выполнение со следующей строки.

**Пример:**

```c
#include <stdio.h>
#include <unistd.h>

int main(void)
{
    pid_t pid = fork();

    if (pid == -1) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        printf("Я ребёнок, PID = %d\n", getpid());
    } else {
        printf("Я родитель, PID ребёнка = %d\n", pid);
    }

    return 0;
}
```

**Возможный вывод:**

```
Я родитель, PID ребёнка = 12345
Я ребёнок, PID = 12345
```

Порядок строк **не гарантирован** — оба процесса выполняются параллельно.

## 4. Что копируется при `fork`

`fork` создаёт **полную копию** процесса:

| Что | Копируется? |
|-----|:-----------:|
| Адресное пространство (память) | ✅ |
| Переменные | ✅ (значения) |
| Открытые дескрипторы | ✅ (общие) |
| Текущий каталог | ✅ |
| Переменные окружения | ✅ |
| Буфер `stdio` | ✅ |

⚠️ **Память копируется**, но **не сразу** — используется механизм **copy-on-write**. Пока ни один процесс не пишет, страницы общие. При записи — копируется только изменённая страница. Это экономит память.

**Пример:**

```c
int x = 5;
pid_t pid = fork();

if (pid == 0) {
    x = 10;   // изменяется только в ребёнке
}

// в родителе x останется 5, в ребёнке — 10
```

⚠️ **Дескрипторы общие.** Если ребёнок закроет файл — у родителя он тоже закроется (точнее, общая файловая позиция). Это часто путает.

## 5. `wait` — ожидание завершения

```c
#include <sys/wait.h>

pid_t wait(int *status);
```

**Что делает:** ждёт завершения **любого** дочернего процесса.

**Возвращает:** PID завершившегося ребёнка или `-1`.

**Параметр `status`** — сюда записывается статус завершения. Можно передать `NULL`, если статус не важен.

**Пример:**

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void)
{
    pid_t pid = fork();

    if (pid == 0) {
        printf("Ребёнок работает\n");
        sleep(2);
        printf("Ребёнок завершается\n");
        return 42;
    }

    int status;
    wait(&status);

    if (WIFEXITED(status)) {
        printf("Ребёнок завершился с кодом %d\n", WEXITSTATUS(status));
    }

    return 0;
}
```

**Вывод:**

```
Ребёнок работает
Ребёнок завершается
Ребёнок завершился с кодом 42
```

## 6. Разбор `status`

Параметр `status` — это **не просто код возврата**. Это упакованное значение, которое содержит много информации. Для его расшифровки есть **макросы**:

| Макрос | Что проверяет |
|--------|---------------|
| `WIFEXITED(status)` | Завершился нормально (`exit`/`return`)? |
| `WEXITSTATUS(status)` | Код завершения (0–255) |
| `WIFSIGNALED(status)` | Убит сигналом? |
| `WTERMSIG(status)` | Номер сигнала |
| `WIFSTOPPED(status)` | Остановлен? |
| `WSTOPSIG(status)` | Номер сигнала остановки |

**Пример:**

```c
int status;
wait(&status);

if (WIFEXITED(status)) {
    printf("Код выхода: %d\n", WEXITSTATUS(status));
} else if (WIFSIGNALED(status)) {
    printf("Убит сигналом: %d\n", WTERMSIG(status));
}
```

⚠️ **Проверяйте `WIFEXITED` перед `WEXITSTATUS`** — иначе можете получить неправильное число.

## 7. `waitpid` — ожидание конкретного процесса

```c
#include <sys/wait.h>

pid_t waitpid(pid_t pid, int *status, int options);
```

**Что делает:** ждёт завершения **конкретного** дочернего процесса (или группы).

**Параметры:**

| Параметр | Что означает |
|----------|--------------|
| `pid > 0` | Ждать процесса с указанным PID |
| `pid == 0` | Ждать любого ребёнка из группы родителя |
| `pid == -1` | Ждать любого ребёнка (как `wait`) |
| `pid < -1` | Ждать любого из группы `|pid|` |

**Опции:**

| Опция | Что делает |
|-------|-----------|
| `0` | Блокирующее ожидание |
| `WNOHANG` | Не блокировать, вернуть 0, если никто не завершился |
| `WUNTRACED` | Сообщать об остановленных |

**Пример:**

```c
pid_t pid = fork();

if (pid == 0) {
    sleep(3);
    return 7;
}

int status;
pid_t finished = waitpid(pid, &status, 0);

if (WIFEXITED(status)) {
    printf("PID %d завершился с кодом %d\n",
           finished, WEXITSTATUS(status));
}
```

**Неблокирующая проверка:**

```c
pid_t result = waitpid(pid, &status, WNOHANG);
if (result == 0) {
    printf("Ребёнок ещё работает\n");
} else if (result == pid) {
    printf("Ребёнок завершился\n");
}
```

## 8. `wait` vs `waitpid`

| Характеристика | `wait` | `waitpid` |
|----------------|:------:|:---------:|
| Кого ждёт | Любого ребёнка | Конкретного (по PID) |
| Неблокирующий режим | ❌ | ✅ (`WNOHANG`) |
| Опции | Нет | Много |
| Гибкость | Меньше | Больше |

**Правило:** используйте `waitpid`, если нужно контролировать, какого ребёнка ждать, или если нужен неблокирующий режим.

## 9. Зомби и сироты

### Зомби (Zombie)

Если ребёнок завершился, а родитель **не вызвал `wait`**, ребёнок остаётся в состоянии **зомби**. Он уже не работает, но занимает запись в таблице процессов.

```c
if (fork() == 0) {
    return 0;    // ребёнок завершился
}
// родитель не вызвал wait — зомби появится
```

**Как избежать:**
- Всегда вызывать `wait` или `waitpid`.
- Игнорировать сигнал `SIGCHLD` — тогда ядро само уберёт зомби.
- Использовать двойной `fork`.

### Сирота (Orphan)

Если **родитель** завершился раньше ребёнка, ребёнок становится **сиротой**. Его усыновляет `init` (PID 1). Это **не проблема** — `init` корректно обработает завершение.

## 10. Полный пример: родитель и двое детей

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void)
{
    pid_t pid1 = fork();

    if (pid1 == 0) {
        printf("Ребёнок 1 работает (PID %d)\n", getpid());
        sleep(2);
        printf("Ребёнок 1 завершается\n");
        return 1;
    }

    pid_t pid2 = fork();

    if (pid2 == 0) {
        printf("Ребёнок 2 работает (PID %d)\n", getpid());
        sleep(1);
        printf("Ребёнок 2 завершается\n");
        return 2;
    }

    // Родитель ждёт обоих
    int status;
    waitpid(pid1, &status, 0);
    printf("Ребёнок %d завершился с кодом %d\n",
           pid1, WEXITSTATUS(status));

    waitpid(pid2, &status, 0);
    printf("Ребёнок %d завершился с кодом %d\n",
           pid2, WEXITSTATUS(status));

    return 0;
}
```

**Возможный вывод:**

```
Ребёнок 1 работает (PID 1234)
Ребёнок 2 работает (PID 1235)
Ребёнок 2 завершается
Ребёнок 1 завершается
Ребёнок 1234 завершился с кодом 1
Ребёнок 1235 завершился с кодом 2
```

## 11. Типичные ошибки

| Ошибка | Что не так | Решение |
|--------|-----------|---------|
| Забыли `wait` | Зомби | Всегда ждать |
| Считают, что `fork` возвращает один раз | Путаница | Помнить про два возврата |
| Изменение переменной в ребёнке | Родитель не увидит | Использовать `pipe`/разделяемую память |
| Забыли закрыть дескрипторы | Утечка | Закрывать в обоих процессах |
| Не проверяют `-1` | Работа с невалидным PID | Проверять всегда |
| `WEXITSTATUS` без `WIFEXITED` | Мусор | Сначала проверять |
| Дедлок через `pipe` | Оба ждут друг друга | Закрывать ненужные концы |

## 12. Итоги

- **`fork`** — создаёт копию процесса; возвращается дважды.
- **`getpid`/`getppid`** — PID процесса и его родителя.
- **`wait`** — ждёт любого ребёнка.
- **`waitpid`** — ждёт конкретного, есть неблокирующий режим.
- **`status`** — упакованное значение; разбирается макросами `WIF*`.
- **Зомби** — ребёнок, которого не дождались.
- **Сирота** — ребёнок, чей родитель завершился.
