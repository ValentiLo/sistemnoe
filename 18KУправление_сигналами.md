## 2. Что такое сигнал

**Сигнал** — это асинхронное уведомление, которое ядро отправляет процессу. Сигнал может возникнуть:

- от пользователя (нажатие `Ctrl+C` → `SIGINT`),
- от другого процесса (`kill`),
- от ядра (деление на ноль, ошибка сегментации),
- по таймеру (`alarm`).

**Схема:**

```
Источник сигнала → ядро → процесс
                          ↓
                    обработчик
```

**Что можно сделать с сигналом:**

| Действие | Что означает |
|----------|--------------|
| **Обработать** | Своя функция-обработчик |
| **Игнорировать** | `SIG_IGN` |
| **По умолчанию** | `SIG_DFL` — обычно завершение |

---

## 3. Основные сигналы

| Сигнал | Номер | Действие по умолчанию | Что означает |
|--------|:-----:|----------------------|--------------|
| `SIGINT` | 2 | Завершение | Ctrl+C |
| `SIGTERM` | 15 | Завершение | Вежливое завершение (`kill`) |
| `SIGKILL` | 9 | Завершение | **Нельзя обработать** |
| `SIGSTOP` | 19 | Остановка | **Нельзя обработать** |
| `SIGCONT` | 18 | Продолжить | Возобновить после stop |
| `SIGSEGV` | 11 | Завершение | Ошибка сегментации |
| `SIGFPE` | 8 | Завершение | Деление на ноль |
| `SIGALRM` | 14 | Завершение | Сработал `alarm` |
| `SIGCHLD` | 17 | Игнорирование | Ребёнок завершился |
| `SIGPIPE` | 13 | Завершение | Запись в закрытый канал |
| `SIGUSR1` | 10 | Завершение | Пользовательский |
| `SIGUSR2` | 12 | Завершение | Пользовательский |

⚠️ **`SIGKILL` и `SIGSTOP` нельзя перехватить или проигнорировать.** Это гарантия ядра.

## 4. `signal` — простой обработчик

```c
#include <signal.h>

typedef void (*sighandler_t)(int);

sighandler_t signal(int signum, sighandler_t handler);
```

**Параметры:**
- `signum` — номер сигнала.
- `handler` — функция-обработчик или `SIG_IGN`/`SIG_DFL`.

**Возвращает:** предыдущий обработчик или `SIG_ERR`.

**Пример:**

```c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

void handler(int sig)
{
    printf("Получен сигнал %d\n", sig);
}

int main(void)
{
    signal(SIGINT, handler);

    while (1) {
        printf("Работаю...\n");
        sleep(1);
    }
    return 0;
}
```

**Что произойдёт:**
- При нажатии `Ctrl+C` вместо завершения программы вызовется `handler`.
- Программа продолжит работу.

⚠️ **`signal` устарела.** Поведение зависит от системы. Рекомендуется `sigaction`.

## 5. `sigaction` — надёжный обработчик

```c
#include <signal.h>

int sigaction(int signum, const struct sigaction *act,
              struct sigaction *oldact);
```

**Структура `struct sigaction`:**

```c
struct sigaction {
    void (*sa_handler)(int);          // обработчик (простой)
    void (*sa_sigaction)(int, siginfo_t *, void *);  // расширенный
    sigset_t sa_mask;                 // блокируемые сигналы
    int sa_flags;                     // флаги
    void (*sa_restorer)(void);        // устаревшее
};
```

**Основные поля:**

| Поле | Что означает |
|------|--------------|
| `sa_handler` | Функция-обработчик |
| `sa_mask` | Сигналы, блокируемые на время обработки |
| `sa_flags` | Поведение (`SA_RESTART`, `SA_SIGINFO` и т.д.) |

**Флаги:**

| Флаг | Что делает |
|------|-----------|
| `SA_RESTART` | Перезапускать системные вызовы |
| `SA_SIGINFO` | Использовать `sa_sigaction` (расширенную) |
| `SA_RESETHAND` | Сбросить обработчик после вызова |
| `SA_NODEFER` | Не блокировать сигнал во время обработки |
| `SA_NOCLDSTOP` | Не сообщать о приостановке детей |

**Пример:**

```c
#include <stdio.h>
#include <signal.h>
#include <string.h>
#include <unistd.h>

void handler(int sig)
{
    printf("Получен сигнал: %d\n", sig);
}

int main(void)
{
    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART;

    if (sigaction(SIGINT, &sa, NULL) == -1) {
        perror("sigaction");
        return 1;
    }

    while (1) {
        printf("Работаю...\n");
        sleep(1);
    }
    return 0;
}
```

**Почему `sigaction` лучше `signal`:**
- Явное поведение (не зависит от системы).
- Можно указать маску сигналов.
- Можно использовать `SA_RESTART`.
- Поддерживает расширенную информацию о сигнале (`SA_SIGINFO`).

## 6. `kill` — отправка сигнала

```c
#include <signal.h>

int kill(pid_t pid, int sig);
```

**Параметры:**

| `pid` | Кому посылает |
|:-----:|---------------|
| `> 0` | Процессу с указанным PID |
| `0` | Всем в группе вызывающего |
| `-1` | Всем, кому можно |
| `< -1` | Группе `|pid|` |

**Возвращает:** `0` или `-1`.

**Пример:**

```c
kill(12345, SIGTERM);   // послать SIGTERM процессу 12345
kill(getpid(), SIGUSR1); // послать себе
```

**Специальные случаи:**
- `kill(pid, 0)` — **проверить**, существует ли процесс и есть ли права.
- `kill(pid, SIGKILL)` — **убить** без возможности обработать.

## 7. Что происходит при получении сигнала

1. **Ядро прерывает** выполнение процесса.
2. **Сохраняется контекст** (регистры, стек).
3. **Вызывается обработчик**, если он есть.
4. **После возврата** из обработчика **восстанавливается контекст**.
5. Выполнение **продолжается** с прерванного места.

⚠️ **Обработчик должен быть коротким и безопасным.** Внутри нельзя вызывать функции, которые не являются **async-signal-safe** (`printf`, `malloc` — **небезопасны**).

**Список async-signal-safe:**
- `write`, `read`, `open`, `close`
- `_exit`, `_Exit`
- `signal`, `sigaction`
- `kill`
- `wait`, `waitpid`
- `sleep` (не всегда)

**Нельзя использовать:**
- `printf` (может быть заблокирован)
- `malloc` / `free`
- `strlen` и большинство функций `<string.h>`

⚠️ **Если нужно что-то сделать из обработчика — установите флаг.**

```c
volatile sig_atomic_t flag = 0;

void handler(int sig)
{
    flag = 1;   // только запись флага — безопасно
}

int main(void)
{
    signal(SIGINT, handler);
    while (!flag) {
        sleep(1);
    }
    printf("Сигнал получен\n");
    return 0;
}
```

## 8. `SIGINT` и `SIGTERM` на практике

| Сигнал | Как возникает | Как обрабатывать |
|--------|---------------|------------------|
| `SIGINT` | Ctrl+C | Перехватить и корректно завершиться |
| `SIGTERM` | `kill` | Перехватить и корректно завершиться |
| `SIGKILL` | `kill -9` | **Нельзя перехватить** |

**Правильный шаблон завершения:**

```c
#include <stdio.h>
#include <signal.h>
#include <stdlib.h>
#include <unistd.h>

volatile sig_atomic_t stop = 0;

void on_signal(int sig)
{
    stop = 1;
}

int main(void)
{
    struct sigaction sa;
    sa.sa_handler = on_signal;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;

    sigaction(SIGINT, &sa, NULL);
    sigaction(SIGTERM, &sa, NULL);

    while (!stop) {
        printf("Работаю...\n");
        sleep(1);
    }

    printf("Завершаюсь корректно\n");
    // освободить ресурсы
    return 0;
}
```

**Что происходит:**
- При `Ctrl+C` или `kill` устанавливается флаг `stop`.
- Основной цикл **сам** завершается.
- Выполняется корректное завершение.

⚠️ **Не делайте тяжёлых операций в обработчике** — только флаг.

## 9. `SIGCHLD` — завершение ребёнка

Когда дочерний процесс завершается, ядро отправляет родителю `SIGCHLD`.

**По умолчанию** сигнал игнорируется, но ребёнок остаётся **зомби**, пока родитель не вызовет `wait`.

**Пример:**

```c
void on_sigchld(int sig)
{
    int status;
    while (waitpid(-1, &status, WNOHANG) > 0) {
        // убираем зомби
    }
}

int main(void)
{
    struct sigaction sa;
    sa.sa_handler = on_sigchld;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART | SA_NOCLDSTOP;

    sigaction(SIGCHLD, &sa, NULL);

    // ... создаём детей ...
}
```

⚠️ **Вызывайте `waitpid` в цикле `while`** — может быть несколько завершившихся детей.

## 10. Типичные ошибки

| Ошибка | Что не так | Решение |
|--------|-----------|---------|
| `printf` в обработчике | Не async-signal-safe | Установить флаг |
| Забыли `memset(&sa, 0, ...)` | Мусор в полях | Обнулить |
| Не проверяют возврат `sigaction` | Ошибка останется | Проверять `-1` |
| Используют `signal` | Поведение зависит от системы | Использовать `sigaction` |
| Игнорируют `SIGCHLD` | Зомби | Обрабатывать |
| `kill` с неверным PID | Сигнал не дойдёт | Проверять `-1` |
| Не ставят `SA_RESTART` | Системные вызовы прерываются | Добавить флаг |
| `volatile sig_atomic_t` забыли | Компилятор оптимизирует флаг | Объявлять правильно |

## 11. Итоги

- **Сигнал** — асинхронное уведомление от ядра.
- **`SIGINT`** — Ctrl+C, **`SIGTERM`** — `kill`.
- **`SIGKILL`** нельзя перехватить — гарантия завершения.
- **`signal`** — простой, но устаревший.
- **`sigaction`** — надёжный, с маской и флагами.
- **`kill`** — отправка сигнала.
- **Обработчик** — короткий, только `volatile sig_atomic_t`.
- **`SIGCHLD`** — помогает убирать зомби.
