# Мониторинг файловой системы в C

**Дисциплина:** Основы программирования на языке Си  
**Тема:** `inotify`, `stat`, сравнение снимков  
**Тип занятия:** лекция (2 ч)

---

## 1. Цели и задачи

**Цель:** научиться отслеживать изменения в файловой системе — появление, удаление, изменение файлов.

**Задачи:**
- Освоить `stat` — получение информации о файле.
- Освоить `inotify` — событийное отслеживание изменений.
- Разобраться со сравнением снимков — периодическим сканированием.
- Понять, когда какой подход применять.

**Компетенции:** ОК 01, ОК 02, ПК 1.1, ПК 1.2.

---

## 2. Три подхода к мониторингу

| Подход | Как работает | Когда использовать |
|--------|-------------|-------------------|
| **Сравнение снимков** | Периодически сканируем каталог и сравниваем с предыдущим | Нечастые проверки, аудит |
| **`stat` по таймеру** | Опрашиваем один файл через равные промежутки | Проверка конкретного файла |
| **`inotify`** | Ядро само сообщает об изменениях | Реальное время, высокая точность |

Первый и второй — **опрос** (polling). Третий — **событийный** (event-driven). Он эффективнее, но сложнее.

---

## 3. Подход 1. Сравнение снимков

**Идея:** сохранить состояние каталога в структуру, затем периодически пересобирать и сравнивать.

**Что сравнивать:**

| Поле `struct stat` | Что показывает |
|--------------------|----------------|
| `st_size` | Размер файла |
| `st_mtime` | Время изменения содержимого |
| `st_ctime` | Время изменения метаданных |
| `st_ino` | Номер inode (меняется при пересоздании) |
| `st_mode` | Права и тип |

**Структура снимка:**

```c
struct Snapshot {
    char path[PATH_MAX];
    off_t size;
    time_t mtime;
    ino_t ino;
};
```

**Алгоритм:**

1. Обойти каталог через `opendir` + `readdir`.
2. Для каждого файла вызвать `stat`, сохранить в массив.
3. Подождать.
4. Снова обойти каталог, сравнить с сохранённым.
5. Вывести различия.

**Пример функции сравнения:**

```c
if (a.size != b.size)
    printf("Размер изменился: %s\n", a.path);
if (a.mtime != b.mtime)
    printf("Содержимое изменилось: %s\n", a.path);
if (a.ino != b.ino)
    printf("Файл пересоздан: %s\n", a.path);
```

**Плюсы:**
- Не нужны специальные API — только `stat` и обход каталога.
- Работает на любой файловой системе.
- Просто реализовать.

**Минусы:**
- Задержка между проверками.
- Нагрузка на диск при частом сканировании.
- Можно пропустить быстрое изменение (файл изменился и вернулся к прежнему состоянию).

## 4. Подход 2. `stat` по таймеру

**Идея:** следить за **одним** файлом, периодически проверяя его метаданные.

```c
#include <sys/stat.h>
#include <time.h>
#include <stdio.h>
#include <unistd.h>

int main(void)
{
    struct stat st, prev;
    stat("data.txt", &prev);

    while (1) {
        sleep(2);
        if (stat("data.txt", &st) == -1) {
            perror("stat");
            break;
        }

        if (st.st_mtime != prev.st_mtime ||
            st.st_size != prev.st_size) {
            printf("Файл изменился!\n");
            prev = st;
        }
    }
    return 0;
}
```

**Когда использовать:**
- Простые задачи.
- Если нельзя использовать `inotify` (например, другая ОС).
- Для учебных целей.

**Минусы:**
- Постоянный опрос — нагрузка на CPU.
- Задержка до момента обнаружения.
- Не масштабируется на много файлов.

## 5. Подход 3. `inotify` — событийный

**`inotify`** — механизм ядра Linux, который **сам сообщает** программе об изменениях в файловой системе. Не нужно опрашивать — ядро присылает события.

**Основные функции (`<sys/inotify.h>`):**

| Функция | Что делает |
|---------|-----------|
| `inotify_init1(flags)` | Создаёт inotify-экземпляр, возвращает дескриптор |
| `inotify_add_watch(fd, path, mask)` | Добавляет путь для отслеживания |
| `inotify_rm_watch(fd, wd)` | Убирает отслеживание |
| `read(fd, buf, size)` | Читает события |

**Основные события (`mask`):**

| Флаг | Что означает |
|------|--------------|
| `IN_CREATE` | Создан файл/каталог |
| `IN_DELETE` | Удалён файл/каталог |
| `IN_MODIFY` | Изменено содержимое |
| `IN_ATTRIB` | Изменены метаданные (права, время) |
| `IN_MOVED_FROM` | Файл выбыл из каталога |
| `IN_MOVED_TO` | Файл прибыл в каталог |
| `IN_CLOSE_WRITE` | Файл закрыт после записи |
| `IN_ALL_EVENTS` | Все события |

**Структура `struct inotify_event`:**

```c
struct inotify_event {
    int      wd;       // дескриптор watch
    uint32_t mask;     // что произошло
    uint32_t cookie;   // связь между MOVED_FROM и MOVED_TO
    uint32_t len;      // длина имени
    char     name[];   // имя файла (если есть)
};
```

## 6. Пример `inotify`

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/inotify.h>
#include <limits.h>

#define BUF_LEN (10 * (sizeof(struct inotify_event) + NAME_MAX + 1))

int main(void)
{
    int fd = inotify_init1(IN_NONBLOCK);
    if (fd == -1) {
        perror("inotify_init1");
        return 1;
    }

    int wd = inotify_add_watch(fd, ".", IN_ALL_EVENTS);
    if (wd == -1) {
        perror("inotify_add_watch");
        close(fd);
        return 1;
    }

    char buf[BUF_LEN];
    while (1) {
        ssize_t n = read(fd, buf, sizeof(buf));
        if (n == -1) {
            usleep(100000);   // 0.1 сек
            continue;
        }

        for (ssize_t i = 0; i < n; ) {
            struct inotify_event *ev = (struct inotify_event *)&buf[i];

            if (ev->mask & IN_CREATE)
                printf("Создан: %s\n", ev->name);
            if (ev->mask & IN_DELETE)
                printf("Удалён: %s\n", ev->name);
            if (ev->mask & IN_MODIFY)
                printf("Изменён: %s\n", ev->name);
            if (ev->mask & IN_ATTRIB)
                printf("Метаданные: %s\n", ev->name);

            i += sizeof(struct inotify_event) + ev->len;
        }
    }

    inotify_rm_watch(fd, wd);
    close(fd);
    return 0;
}
```

⚠️ **Обратите внимание:** чтение идёт **блоками**, в которых может лежать **несколько** событий. Нужно идти по буферу с шагом `sizeof(struct inotify_event) + ev->len`.

## 7. Особенности `inotify`

**Что нужно знать:**

1. **Не рекурсивный.** Если добавить watch на каталог, события внутри **подкаталогов** приходить не будут. Нужно добавлять watch на каждый подкаталог отдельно.

2. **Привязан к inode.** Если файл пересоздан (удалён и создан заново), watch на него **теряется**.

3. **Может терять события.** При переполнении очереди ядро присылает `IN_Q_OVERFLOW`. Нужно предусмотреть обработку.

4. **Имя файла не всегда есть.** Для событий на сам каталог `name` пустое.

5. **`IN_MOVED_FROM` + `IN_MOVED_TO`** связаны через `cookie` — можно отследить, куда переехал файл.

## 8. Гибридный подход

На практике часто комбинируют:

- **`inotify`** — основной механизм, даёт события в реальном времени.
- **`stat`** — периодическая проверка состояния (раз в минуту), чтобы поймать пропущенные события.
- **Снимок** — при старте программы, чтобы знать исходное состояние.

**Схема:**

```
Старт → снимок каталога (stat)
   ↓
inotify-поток (события)
   ↓
Раз в N секунд → сравнение снимка
   ↓
Если различия → обновить снимок и сообщить
```

Такой подход даёт **и скорость**, и **надёжность**.

## 9. Типичные ошибки

| Ошибка | Что не так | Решение |
|--------|-----------|---------|
| Сравнивать только `st_mtime` | Быстрое изменение не заметите | Сравнивать `st_size`, `st_ino` тоже |
| Забыли закрыть `inotify` fd | Утечка | `close(fd)` |
| Не обрабатывают `IN_Q_OVERFLOW` | Пропуск событий | Обрабатывать флаг |
| Ждут `inotify` без таймаута | Блокировка | Использовать `IN_NONBLOCK` + `usleep` |
| Игнорируют `-1` от `stat` | Работа с мусором | Проверять всегда |
| Рекурсивный обход без ограничений | Бесконечный цикл по ссылкам | Пропускать `DT_LNK` |
| `read` без проверки размера | Переполнение буфера | Использовать `BUF_LEN` |

## 10. Итоги

- **Сравнение снимков** — просто, но с задержкой.
- **`stat` по таймеру** — для одного файла.
- **`inotify`** — для реального времени, но не рекурсивный.
- **Гибрид** — лучший вариант: `inotify` + периодический `stat`.
- **Всегда проверяйте** `-1` и закрывайте дескрипторы.
- **Сравнивайте** `st_size`, `st_mtime`, `st_ino` — не только одно поле.
