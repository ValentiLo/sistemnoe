## 2. Зачем нужно планирование

Процессов много, а процессор — один (или их мало). ОС должна решить:

- **Кого** запустить следующим.
- **На сколько** — до следующего переключения.
- **Что делать**, если процесс ждёт ввода-вывода.

**Цель планировщика:** справедливо распределить процессорное время и минимизировать время ожидания.

**Основные характеристики:**

| Показатель | Что означает |
|------------|--------------|
| **Время поступления** | Когда процесс появился в системе |
| **Время выполнения** | Сколько CPU ему нужно |
| **Время ожидания** | Сколько он ждал в очереди |
| **Время отклика** | От поступления до завершения |
| **Квант времени** | Сколько дают процессу за раз |

---

## 3. FIFO (First In, First Out)

**Идея:** процессы выполняются в порядке поступления. Кто первый пришёл — того первого и обслуживают.

**Алгоритм:**

1. Процессы выстраиваются в очередь.
2. Первый в очереди получает CPU.
3. Работает **до завершения** (или до блокировки на ввод-вывод).
4. Затем — следующий.

**Пример:**

| Процесс | Поступление | Выполнение |
|---------|:-----------:|:----------:|
| P1 | 0 | 5 |
| P2 | 1 | 3 |
| P3 | 2 | 2 |

**Порядок выполнения:** P1 → P2 → P3.

| Процесс | Ждал | Завершился |
|---------|:----:|:----------:|
| P1 | 0 | 5 |
| P2 | 4 | 8 |
| P3 | 6 | 10 |

**Среднее время ожидания:** (0 + 4 + 6) / 3 = **3.33**

**Плюсы:**
- Просто.
- Справедливо «по очереди».
- Нет переключений — меньше накладных расходов.

**Минусы:**
- **Конвойный эффект**: если первый процесс долгий, все остальные ждут.
- Плохо для интерактивных задач.
- Не учитывает приоритеты.

---

## 4. SJF (Shortest Job First)

**Идея:** первым запускается процесс с **наименьшим временем выполнения**.

**Алгоритм:**

1. Смотрим на все процессы, готовые к выполнению.
2. Выбираем тот, у которого **наименьшее** время CPU.
3. Выполняем до конца.
4. Повторяем.

**Пример** (те же процессы):

| Процесс | Поступление | Выполнение |
|---------|:-----------:|:----------:|
| P1 | 0 | 5 |
| P2 | 1 | 3 |
| P3 | 2 | 2 |

**Порядок:** P1 (единственный в момент 0) → P3 (2) → P2 (3).

| Процесс | Ждал | Завершился |
|---------|:----:|:----------:|
| P1 | 0 | 5 |
| P3 | 3 | 7 |
| P2 | 6 | 10 |

**Среднее время ожидания:** (0 + 3 + 6) / 3 = **3.0**

**Плюсы:**
- **Оптимален** по среднему времени ожидания.
- Хорошо для пакетной обработки.

**Минусы:**
- **Требует знания** времени выполнения заранее.
- Возможен **голод** для долгих процессов.
- Не подходит для интерактивных систем.

**Разновидность — SRTF** (Shortest Remaining Time First): если приходит процесс с меньшим остатком, текущий вытесняется.

## 5. RR (Round Robin)

**Идея:** каждому процессу даётся **квант времени** (`quantum`). Если не успел — становится в конец очереди.

**Алгоритм:**

1. Процессы в очереди.
2. Первый получает CPU на `quantum` единиц.
3. Если за это время завершился — уходит.
4. Если нет — возвращается в **конец** очереди.
5. Следующий получает CPU.

**Пример** (квант = 2):

| Процесс | Поступление | Выполнение |
|---------|:-----------:|:----------:|
| P1 | 0 | 5 |
| P2 | 1 | 3 |
| P3 | 2 | 2 |

**Порядок:**

| Время | Работает | Осталось |
|:-----:|:--------:|:--------:|
| 0–2 | P1 | 3 |
| 2–4 | P2 | 1 |
| 4–6 | P3 | 0 ✓ |
| 6–8 | P1 | 1 |
| 8–9 | P2 | 0 ✓ |
| 9–10 | P1 | 0 ✓ |

**Завершение:**

| Процесс | Завершился | Ожидание |
|---------|:----------:|:--------:|
| P3 | 6 | 2 |
| P2 | 9 | 5 |
| P1 | 10 | 5 |

**Среднее время ожидания:** (5 + 5 + 2) / 3 ≈ **4.0**

**Плюсы:**
- **Справедлив** — никто не ждёт вечно.
- Хорош для **интерактивных** систем.
- Быстрый отклик.

**Минусы:**
- Много **переключений контекста** — накладные расходы.
- Результат зависит от **размера кванта**.
- Среднее время ожидания больше, чем у SJF.

**Как выбрать квант:**
- Слишком мал → много переключений.
- Слишком велик → превращается в FIFO.

---

## 6. Сравнение алгоритмов

Для примера выше:

| Алгоритм | Среднее ожидание | Средний отклик |
|----------|:----------------:|:--------------:|
| FIFO | 3.33 | 5.67 |
| SJF | **3.0** | 5.33 |
| RR (q=2) | 4.0 | 5.67 |

**Вывод:**
- **SJF** — минимум ожидания, но требует знания времён.
- **RR** — справедлив, но чуть медленнее.
- **FIFO** — прост, но уязвим к конвойному эффекту.

## 8. Моделирование на C

**Структура процесса:**

```c
typedef struct {
    int pid;            // ID процесса
    int arrival;        // время поступления
    int burst;          // время выполнения
    int remaining;      // остаток времени
    int start;          // время первого запуска
    int finish;         // время завершения
    int waiting;        // время ожидания
} Process;
```

**Общая схема:**

1. Задать массив процессов.
2. Отсортировать по времени поступления (при необходимости).
3. Пройти по времени, выбирая процесс по стратегии.
4. Подсчитать время ожидания и завершения.

### FIFO — простой обход

```c
int time = 0;
for (int i = 0; i < n; i++) {
    if (time < p[i].arrival)
        time = p[i].arrival;
    p[i].start = time;
    time += p[i].burst;
    p[i].finish = time;
    p[i].waiting = p[i].start - p[i].arrival;
}
```

### SJF — выбор минимального `burst` среди готовых

```c
int done = 0, time = 0;
while (done < n) {
    int idx = -1;
    int best = 999999;
    for (int i = 0; i < n; i++) {
        if (!p[i].done && p[i].arrival <= time) {
            if (p[i].burst < best) {
                best = p[i].burst;
                idx = i;
            }
        }
    }
    if (idx == -1) { time++; continue; }   // никто ещё не пришёл
    p[idx].start = time;
    time += p[idx].burst;
    p[idx].finish = time;
    p[idx].waiting = p[idx].start - p[idx].arrival;
    p[idx].done = 1;
    done++;
}
```

### RR — очередь и квант

```c
int quantum = 2;
int time = 0, done = 0;
int queue[100], head = 0, tail = 0;

// Изначально добавляем процессы, пришедшие в момент 0
for (int i = 0; i < n; i++)
    if (p[i].arrival == 0)
        queue[tail++] = i;

while (done < n) {
    if (head == tail) {         // очередь пуста — ждём
        time++;
        for (int i = 0; i < n; i++)
            if (p[i].arrival == time)
                queue[tail++] = i;
        continue;
    }

    int idx = queue[head++];
    int run = (p[idx].remaining < quantum) ? p[idx].remaining : quantum;

    if (p[idx].start == -1)
        p[idx].start = time;

    time += run;
    p[idx].remaining -= run;

    if (p[idx].remaining == 0) {
        p[idx].finish = time;
        p[idx].waiting = p[idx].finish - p[idx].arrival - p[idx].burst;
        done++;
    } else {
        queue[tail++] = idx;    // вернуть в конец
    }

    // Добавляем процессы, пришедшие за это время
    for (int i = 0; i < n; i++)
        if (p[i].arrival > time - run && p[i].arrival <= time)
            queue[tail++] = i;
}
```

⚠️ В реальной программе нужно аккуратно обрабатывать **моменты прихода** процессов и **порядок** добавления в очередь.

## 10. Типичные ошибки

| Ошибка | Что не так |
|--------|-----------|
| Забыли обработать простой CPU | Никто не готов — надо «пропустить» время |
| Не учитывают приход процесса в середине кванта | Нарушение порядка |
| Ожидание считают как `finish - arrival` | Это **отклик**, а не ожидание |
| `waiting = finish - arrival - burst` | Верно для процесса без вытеснения |
| Квант = 0 | Бесконечный цикл |
| Не добавляют процесс в очередь после `arrival` | Процесс «теряется» |

## 11. Итоги

- **FIFO** — просто, но конвойный эффект.
- **SJF** — оптимален по ожиданию, но требует знания времён.
- **RR** — справедлив, хорош для интерактива, но много переключений.
- **Ключевые метрики:** время ожидания, отклик, число переключений.
- **Моделирование** на C — это таблица процессов и цикл по времени.
