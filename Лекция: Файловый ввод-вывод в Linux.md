# Лекция: Файловый ввод-вывод в Linux (просто и с примерами)

## 1. Что такое файл в Unix

В Unix файл — это **просто последовательность байтов**. Системе всё равно, что внутри: текст, картинка или программа. Она не накладывает никакой структуры. Ваша программа сама решает, как интерпретировать эти байты.

**Важный момент:** в Unix **нет символа «конец файла»** внутри самого файла. Размер файла хранится отдельно, в служебной структуре (inode). Когда программа читает файл и доходит до конца, системный вызов просто возвращает `0` — это и есть сигнал «данных больше нет».

---

## 2. API и ABI — чем отличаются

Прежде чем работать с файлами, нужно понять два термина, которые часто путают.

**API (Application Programming Interface)** — это интерфейс на уровне **исходного кода**. Когда вы пишете `printf("Привет")`, вы используете API стандартной библиотеки C. Компилятор знает, что `printf` принимает строку и возвращает число. Если вы перенесёте код на другую систему с тем же API, он скомпилируется без изменений.

**ABI (Application Binary Interface)** — это интерфейс на уровне **двоичного кода**. Он определяет, как именно функции вызываются в машинных инструкциях: в каком регистре передаётся аргумент, кто очищает стек, как устроены структуры в памяти. Если у двух систем одинаковый ABI, то скомпилированная программа будет работать без перекомпиляции.

**Проще:** API — это «как писать код», ABI — это «как код превращается в машинные команды».

---

## 3. Два способа работы с файлами

В Linux есть два уровня ввода-вывода:

| Уровень | Что используется | Примеры функций | Особенности |
|---------|------------------|-----------------|-------------|
| **Системные вызовы** | Напрямую к ядру | `open`, `read`, `write`, `close` | Без буферизации, быстро для больших блоков, зависят от ОС |
| **Библиотечные функции** | Обёртка над системными вызовами | `fopen`, `fscanf`, `fprintf`, `fgets`, `fclose` | С буферизацией, переносимы, удобны для форматирования |

**Правило:** для обычных задач используйте библиотечные функции (`fopen`/`fprintf`). Для системного программирования, где важна точная синхронизация или работа с устройствами, — системные вызовы (`open`/`read`/`write`).

## 4. Системные вызовы: работа с файлами

### 4.1. Открытие файла — `open()`

```c
#include <fcntl.h>
#include <unistd.h>

int fd = open("file.txt", O_RDONLY);
```

**Что возвращает:** целое число — **файловый дескриптор** (fd). Это номер, по которому система узнаёт файл. Если файл открыть не удалось — возвращается `-1`.

**Флаги (второй аргумент):**

| Флаг | Что делает |
|------|------------|
| `O_RDONLY` | Только чтение |
| `O_WRONLY` | Только запись |
| `O_RDWR` | Чтение и запись |
| `O_CREAT` | Создать файл, если его нет |
| `O_TRUNC` | Очистить файл (обрезать до нуля) |
| `O_APPEND` | Все записи — в конец файла |
| `O_EXCL` | Ошибка, если файл уже существует (работает вместе с `O_CREAT`) |
| `O_SYNC` | Ждать физической записи на диск |

**Третий аргумент (права доступа):** нужен только при `O_CREAT`. Например, `0644` — владелец читает и пишет, остальные только читают.

**Пример:**
```c
int fd = open("log.txt", O_WRONLY | O_CREAT | O_APPEND, 0644);
```
Открывает `log.txt` для записи. Если файла нет — создаёт с правами `0644`. Все записи идут в конец.

---

### 4.2. Запись в файл — `write()`

```c
#include <unistd.h>

ssize_t write(int fd, const void *buf, size_t count);
```

**Что делает:** записывает `count` байт из буфера `buf` в файл `fd`.

**Что возвращает:** количество **реально записанных** байт. Может быть меньше `count`, если на диске кончилось место.

**Пример:**
```c
const char *text = "Привет, мир!\n";
ssize_t n = write(fd, text, strlen(text));
```

---

### 4.3. Чтение из файла — `read()`

```c
ssize_t read(int fd, void *buf, size_t count);
```

**Что делает:** читает до `count` байт из файла `fd` в буфер `buf`.

**Что возвращает:**
- больше нуля — сколько байт прочитано;
- `0` — конец файла;
- `-1` — ошибка.

**Пример:**
```c
char buf[1024];
ssize_t n;
while ((n = read(fd, buf, sizeof(buf))) > 0) {
    write(1, buf, n);   // 1 — это stdout
}
```

---

### 4.4. Закрытие файла — `close()`

```c
int close(int fd);
```

Закрывает файл и освобождает дескриптор. Если не закрыть — система закроет сама при завершении программы, но лучше делать это явно.

## 5. Пример: копирование файла через системные вызовы

```c
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main(int argc, char *argv[]) {
    if (argc != 3) {
        fprintf(stderr, "Использование: %s вход выход\n", argv[0]);
        return 1;
    }

    int fd_in = open(argv[1], O_RDONLY);
    if (fd_in == -1) {
        perror("open вход");
        return 2;
    }

    int fd_out = open(argv[2], O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd_out == -1) {
        perror("open выход");
        close(fd_in);
        return 3;
    }

    char buf[4096];
    ssize_t n;
    while ((n = read(fd_in, buf, sizeof(buf))) > 0) {
        write(fd_out, buf, n);
    }

    close(fd_in);
    close(fd_out);
    return 0;
}
```

**Как это работает:**
1. Проверяем аргументы.
2. Открываем первый файл на чтение, второй — на запись (создаём или очищаем).
3. В цикле читаем блоки по 4096 байт и сразу пишем их во второй файл.
4. Цикл заканчивается, когда `read()` вернёт `0` (конец файла).
5. Закрываем оба файла.

## 6. Библиотечные функции: `fopen` и компания

### 6.1. `fopen` — открытие файла

```c
#include <stdio.h>

FILE *f = fopen("file.txt", "r");
```

**Что возвращает:** указатель `FILE *`. Если файл не открылся — `NULL`.

**Режимы:**

| Режим | Что делает |
|-------|------------|
| `"r"` | Чтение (файл должен существовать) |
| `"w"` | Запись (создаёт или очищает) |
| `"a"` | Дозапись в конец |
| `"r+"` | Чтение и запись |
| `"w+"` | Чтение и запись (создаёт или очищает) |
| `"a+"` | Чтение и дозапись |
| `"rb"`, `"wb"` | То же, но в двоичном режиме |

---

### 6.2. Запись — `fprintf`, `fputs`, `fputc`

```c
fprintf(f, "Число: %d\n", 42);   // форматированный вывод
fputs("Просто строка\n", f);     // строка
fputc('A', f);                   // один символ
```

---

### 6.3. Чтение — `fscanf`, `fgets`, `fgetc`

```c
int x;
fscanf(f, "%d", &x);             // читает число

char line[256];
fgets(line, sizeof(line), f);    // читает строку

int c = fgetc(f);                // читает один символ
```

---

### 6.4. Закрытие — `fclose`

```c
fclose(f);
```

## 7. Буферизация — зачем она нужна

Когда вы пишете `fprintf(f, "Привет")`, данные **не сразу** попадают на диск. Сначала они накапливаются в буфере в памяти программы. Когда буфер заполнится (обычно 4–8 КБ), только тогда данные уйдут в ядро, а оттуда — на диск.

**Зачем:** каждое обращение к диску — это медленная операция. Если писать по одному байту, программа будет работать в тысячи раз медленнее. Буфер собирает данные и отправляет их блоками.

**Три режима буферизации:**

| Режим | Когда сбрасывается буфер | Для чего используется |
|-------|--------------------------|----------------------|
| **Блочная** | Когда буфер полон | Файлы на диске |
| **Строчная** | При встрече `\n` | Терминал (stdout) |
| **Небуферизованная** | Сразу | stderr (вывод ошибок) |

**Принудительный сброс:** `fflush(f)`. Нужен, если вы хотите, чтобы данные точно попали на диск прямо сейчас (например, в логгере).

## 8. Пример: логгер, который пишет каждую секунду

```c
#include <stdio.h>
#include <time.h>
#include <unistd.h>

int main(void) {
    FILE *f = fopen("log.txt", "a");
    if (!f) {
        perror("fopen");
        return 1;
    }

    while (1) {
        time_t now = time(NULL);
        struct tm *t = localtime(&now);
        char buf[64];
        strftime(buf, sizeof(buf), "%Y-%m-%d %H:%M:%S", t);

        fprintf(f, "%s\n", buf);
        fflush(f);   // сбрасываем буфер, чтобы данные сразу попали на диск

        sleep(1);
    }

    fclose(f);
    return 0;
}
```

**Что важно:**
- `fopen("log.txt", "a")` — открывает в режиме дозаписи.
- `fflush(f)` — без этого данные могли бы «застрять» в буфере, и архиватор не увидел бы изменений.
- `sleep(1)` — пауза 1 секунда.

## 9. Пример: архиватор логов раз в 5 секунд

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>
#include <unistd.h>
#include <sys/stat.h>

int main(void) {
    mkdir("archive", 0755);

    while (1) {
        sleep(5);

        struct stat st;
        if (stat("log.txt", &st) != 0) {
            continue;
        }

        time_t created = st.st_mtime;
        struct tm *t = localtime(&created);
        char name[128];
        strftime(name, sizeof(name), "archive/log_%Y%m%d_%H%M%S", t);

        char cmd[512];
        snprintf(cmd, sizeof(cmd), "mv log.txt %s.txt", name);
        system(cmd);

        snprintf(cmd, sizeof(cmd), "gzip %s.txt", name);
        system(cmd);

        FILE *f = fopen("log.txt", "w");
        if (f) fclose(f);
    }

    return 0;
}
```

**Что важно:**
- `stat("log.txt", &st)` — получает метаданные файла, включая время последнего изменения (`st.st_mtime`).
- Имя архива формируется на основе этого времени.
- `system("mv ...")` перемещает файл, `system("gzip ...")` сжимает.
- `fopen("log.txt", "w")` создаёт новый пустой файл, чтобы логгер продолжал работу.

## 10. Специальные файлы: трубы (`pipe`) и перенаправление

### Что такое `pipe`

`pipe` (труба) — это механизм, который связывает вывод одной программы со вводом другой. Например:

```bash
ls | grep "txt"
```

Здесь вывод `ls` идёт не на экран, а на вход `grep`.

### Перенаправление (`redirect`)

```bash
program > file.txt
```
Вывод программы идёт в файл, а не на экран.

```bash
program < file.txt
```
Ввод программы берётся из файла.

**Разница между `|` и `>`:**
- `>` перенаправляет вывод **в файл**.
- `|` перенаправляет вывод **в другую программу**.

## 11. Файловые дескрипторы 0, 1, 2

При запуске любой программы из командной строки система автоматически открывает три файла:

| Дескриптор | Имя | Что это |
|------------|-----|---------|
| `0` | `stdin` | Стандартный ввод (клавиатура) |
| `1` | `stdout` | Стандартный вывод (экран) |
| `2` | `stderr` | Стандартный вывод ошибок (экран) |

**Пример:** `write(1, "Привет", 6)` — выведет «Привет» на экран. `read(0, buf, 100)` — прочитает строку с клавиатуры.

## 12. Создание копии дескриптора — `dup()`

`dup(fd)` создаёт **новый** файловый дескриптор, который указывает на тот же файл и ту же позицию. Это используется для перенаправления ввода-вывода.

**Пример:**
```c
close(1);                              // закрываем stdout
open("out.txt", O_WRONLY | O_CREAT, 0644);  // файл займёт дескриптор 1
printf("Это уйдёт в файл\n");          // printf пишет в дескриптор 1 — то есть в файл
```

**Что произошло:** мы закрыли stdout (дескриптор 1), затем открыли файл. Файл получил первый свободный дескриптор — 1. Теперь всё, что пишется в stdout, идёт в файл.

## 13. Итог: что выбрать

| Ситуация | Что использовать |
|----------|------------------|
| Обычная работа с файлами (текст, числа) | `fopen`, `fprintf`, `fscanf`, `fclose` |
| Нужна максимальная скорость на больших блоках | `open`, `read`, `write`, `close` |
| Логгер, который должен писать сразу | `fopen("a")` + `fflush()` |
| Перенаправление вывода | `dup()` или `freopen()` |
| Работа с бинарными данными | `open(..., O_RDWR)` + `read`/`write` |
| Нужно читать построчно | `fgets()` |

**Главное правило:** для 90% задач хватает библиотечных функций. Системные вызовы нужны, когда важна точная синхронизация, работа с устройствами или максимальная производительность.
