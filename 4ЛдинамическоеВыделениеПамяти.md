## 2. Зачем нужно динамическое выделение

До этого мы объявляли массивы так:

```c
int a[100];
```

Размер фиксирован на этапе компиляции. Но что, если число элементов станет известно только во время работы программы — например, пользователь введёт его с клавиатуры? Или файл окажется на 10 000 строк, а не на 100?

**Динамическая память** решает эту проблему: память выделяется **во время выполнения**, ровно столько, сколько нужно. Это делается в области, которая называется **куча (heap)**.

Сравнение двух областей:

| Область | Размер | Время жизни | Освобождение |
|---------|--------|-------------|--------------|
| **Стек** | Ограничен (1–8 МБ) | До конца функции | Автоматическое |
| **Куча** | Ограничен размером ОЗУ | До `free` | Вручную |

Все функции для работы с кучей объявлены в `<stdlib.h>`.

## 3. `malloc` — выделить память

```c
void *malloc(size_t size);
```

- **`size`** — сколько **байт** выделить.
- **Возвращает** указатель на начало блока или `NULL`, если память не выделилась.
- Память **не обнуляется** — там может быть мусор.

**Пример:**

```c
#include <stdlib.h>

int *p = malloc(10 * sizeof(int));   // 10 int
if (p == NULL) {
    perror("malloc");
    return 1;
}
```

⚠️ **`sizeof(int)`, а не `4`** — так надёжнее, работает на любой платформе.

### Что происходит в памяти

```
Стек                    Куча
┌─────┐                ┌──────────────────────┐
│  p  │ ─────────────→ │ [ ][ ][ ][ ] ... [ ]│ 10 int
└─────┘                └──────────────────────┘
```

Указатель `p` лежит на стеке, а данные — в куче.

---

## 4. `calloc` — выделить и обнулить

```c
void *calloc(size_t count, size_t size);
```

- **`count`** — сколько элементов.
- **`size`** — размер одного элемента.
- Возвращает указатель на **обнулённый** блок.
- Если не удалось — `NULL`.

**Пример:**

```c
int *p = calloc(10, sizeof(int));   // 10 int, все = 0
```

**Разница с `malloc`:**

| Функция | Что делает | Инициализация |
|---------|-----------|---------------|
| `malloc(40)` | Выделяет 40 байт | Мусор |
| `calloc(10, sizeof(int))` | Выделяет 40 байт | Все нули |

Когда использовать `calloc`: если нужны **нули** — например, счётчики, массивы индексов, буферы.

---

## 5. `realloc` — изменить размер

```c
void *realloc(void *ptr, size_t new_size);
```

- **`ptr`** — ранее выделенный блок.
- **`new_size`** — новый размер в байтах.
- Возвращает указатель на новый блок или `NULL`.
- **Существующие данные сохраняются**.
- Блок может **переместиться** в памяти.

### Правильное использование

⚠️ **Нельзя присваивать результат напрямую в тот же указатель:**

```c
p = realloc(p, 20 * sizeof(int));   // ❌ утечка, если realloc вернёт NULL
```

Если `realloc` вернёт `NULL`, старый блок **не освобождён**, но указатель `p` уже потерян. Память утечёт.

**Правильно — через временный указатель:**

```c
int *tmp = realloc(p, 20 * sizeof(int));
if (tmp == NULL) {
    free(p);            // старый блок ещё валиден
    return 1;
}
p = tmp;                // только теперь обновляем
```

### Что происходит

```
До realloc:
    [ 10 int ]        ← p

После realloc:
    [ 10 int ]        ← старый блок (освобождён)
    ...
    [ 20 int ]        ← p (новый адрес)
```

`realloc` может расширить блок **на месте** (если после него свободно) или **переместить** в другое место, скопировав данные.

**Особые случаи:**

| Вызов | Эквивалент |
|-------|-----------|
| `realloc(NULL, n)` | `malloc(n)` |
| `realloc(p, 0)` | `free(p)` (по стандарту — реализация зависит) |

## 6. `free` — освободить память

```c
void free(void *ptr);
```

- Освобождает блок, выделенный `malloc`, `calloc` или `realloc`.
- **Всегда** вызывайте после использования.
- После `free` указатель становится «висячим» — присвойте ему `NULL`.

**Пример:**

```c
free(p);
p = NULL;    // защита от случайного использования
```

⚠️ **`free(NULL)` — безопасно**, ничего не делает. Это удобно для проверок.

## 7. Полный пример: динамический массив

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int n;
    printf("Сколько чисел? ");
    scanf("%d", &n);

    int *arr = malloc(n * sizeof(int));
    if (arr == NULL) {
        perror("malloc");
        return 1;
    }

    for (int i = 0; i < n; i++) {
        scanf("%d", &arr[i]);
    }

    long sum = 0;
    for (int i = 0; i < n; i++) {
        sum += arr[i];
    }

    printf("Сумма: %ld\n", sum);

    free(arr);
    arr = NULL;
    return 0;
}
```

## 8. Расширение массива через `realloc`

Классический сценарий: массив растёт по мере поступления данных.

```c
int capacity = 2;
int size = 0;
int *arr = malloc(capacity * sizeof(int));

int x;
while (scanf("%d", &x) == 1) {
    if (size == capacity) {
        capacity *= 2;
        int *tmp = realloc(arr, capacity * sizeof(int));
        if (tmp == NULL) {
            free(arr);
            return 1;
        }
        arr = tmp;
    }
    arr[size++] = x;
}

// используем arr...
free(arr);
```

**Идея:** когда массив заполнен — **удваиваем** размер. Так делают `std::vector` в C++ и `list` в Python.

## 9. Типичные ошибки

| Ошибка | Что не так | Как исправить |
|--------|-----------|---------------|
| Нет проверки на `NULL` | Краш при нехватке памяти | `if (p == NULL) { ... }` |
| Забыли `free` | **Утечка памяти** | Всегда `free(p)` |
| Двойное `free` | UB, краш | `free(p); p = NULL;` |
| Использование после `free` | Мусор / краш | Не обращаться к `p` после `free` |
| `p = realloc(p, ...)` | Утечка при `NULL` | Через временный указатель |
| `malloc(strlen(s))` без `+1` | Нет места для `\0` | `malloc(strlen(s) + 1)` |
| `sizeof` от указателя | Даёт размер указателя, а не массива | Считать вручную |
| `free` для стека | UB | Только для `malloc`/`calloc`/`realloc` |

## 10. Утечки памяти

**Утечка** — когда память выделена, но не освобождена. Программа «съедает» ОЗУ до тех пор, пока система не начнёт тормозить.

**Пример утечки:**

```c
void f(void) {
    int *p = malloc(1000);
    // забыли free
}
```

Каждый вызов `f` теряет 1000 байт. В цикле — быстро исчерпает память.

**Как искать:**

| Инструмент | Что находит |
|-----------|-------------|
| **Valgrind** | Утечки, use-after-free, неинициализированную память |
| **AddressSanitizer** (`-fsanitize=address`) | То же самое, встроено в GCC/Clang |
| **GDB** | Отладка, просмотр памяти |

**Valgrind:**

```bash
valgrind --leak-check=full ./app
```

**AddressSanitizer:**

```bash
gcc -fsanitize=address -g -o app main.c
./app
```

## 11. Динамические структуры данных

Динамическая память — основа для **связных списков**, **деревьев**, **графов**, **хеш-таблиц**. Пример узла списка:

```c
struct Node {
    int data;
    struct Node *next;
};

struct Node *head = malloc(sizeof(struct Node));
head->data = 10;
head->next = NULL;
```

Без `malloc` такие структуры невозможны: заранее неизвестно, сколько будет элементов.

## 12. Сравнение функций

| Функция | Что делает | Обнуляет? | Сохраняет данные? |
|---------|-----------|:---------:|:-----------------:|
| `malloc(n)` | Выделяет `n` байт | ❌ | — |
| `calloc(k, s)` | Выделяет `k × s` байт | ✅ | — |
| `realloc(p, n)` | Меняет размер блока | ❌ | ✅ |
| `free(p)` | Освобождает | — | — |

---

## 13. Итоги

- **`malloc`** — выделить память, не обнуляя.
- **`calloc`** — выделить и обнулить.
- **`realloc`** — изменить размер, данные сохраняются.
- **`free`** — освободить; после — `p = NULL`.
- **Всегда проверяйте `NULL`** после выделения.
- **Каждый `malloc` → `free`.**
- **Утечки** ищут `valgrind` или санитайзеры.
- Динамическая память — база для списков, деревьев, графов.
