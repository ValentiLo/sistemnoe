## 2. Что такое модуль ядра

**Модуль ядра** (Loadable Kernel Module, LKM) — это код, который можно **загрузить в ядро** и **выгрузить из него** без перезагрузки системы.

**Зачем нужны модули:**

- Драйверы устройств (сетевая карта, звук, USB).
- Файловые системы (ext4, NTFS, FAT).
- Сетевые протоколы.
- Системы безопасности (SELinux, AppArmor).

**Где живут модули:**

```
/lib/modules/<версия_ядра>/
```

**Как отличить модуль от обычной программы:**

| Обычная программа | Модуль ядра |
|-------------------|-------------|
| Работает в пользовательском пространстве | Работает в **ядре** |
| Может упасть — не уронит систему | Падение = крах системы |
| Использует `printf` | Использует `printk` |
| Запускается как процесс | Загружается в ядро |
| Может делать всё, что разрешено пользователю | Имеет **полный доступ** к железу |

⚠️ **Модуль ядра — это опасно.** Ошибка в нём может привести к краху системы и потере данных. **Разрабатывайте и тестируйте только в виртуальной машине.**

## 3. Структура простейшего модуля

Минимальный модуль содержит **три обязательные части**:

```c
#include <linux/init.h>
#include <linux/module.h>
#include <linux/kernel.h>

static int __init hello_init(void)
{
    printk(KERN_INFO "Hello, World!\n");
    return 0;   // 0 = загрузка успешна
}

static void __exit hello_exit(void)
{
    printk(KERN_INFO "Goodbye, World!\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Ваше Имя");
MODULE_DESCRIPTION("Простой модуль ядра");
```

**Разбор:**

| Часть | Что означает |
|-------|--------------|
| `#include <linux/init.h>` | Макросы `__init`, `__exit` |
| `#include <linux/module.h>` | Макросы `module_init`, `module_exit`, `MODULE_*` |
| `#include <linux/kernel.h>` | `printk` и уровни логирования |
| `__init` | Функция вызывается только при загрузке; освобождается после |
| `__exit` | Функция вызывается только при выгрузке |
| `module_init(hello_init)` | Указывает, что запускать при загрузке |
| `module_exit(hello_exit)` | Указывает, что запускать при выгрузке |
| `MODULE_LICENSE("GPL")` | Лицензия (без неё ядро «загрязняется») |

⚠️ **`__init` и `__exit`** — это оптимизация: после загрузки код `hello_init` выбрасывается из памяти. То же с `hello_exit` — он нужен только при выгрузке.

## 4. `printk` — вывод в ядро

В модуле **нельзя использовать `printf`**. Вместо него — **`printk`**.

```c
printk(KERN_INFO "Сообщение: %d\n", value);
```

**Уровни логирования:**

| Уровень | Число | Что означает |
|---------|:-----:|--------------|
| `KERN_EMERG` | 0 | Система не работает |
| `KERN_ALERT` | 1 | Требуется немедленное действие |
| `KERN_CRIT` | 2 | Критическая ошибка |
| `KERN_ERR` | 3 | Ошибка |
| `KERN_WARNING` | 4 | Предупреждение |
| `KERN_NOTICE` | 5 | Обратить внимание |
| `KERN_INFO` | 6 | Информация |
| `KERN_DEBUG` | 7 | Отладка |

⚠️ **Уровень пишется слитно с строкой**, без запятой:

```c
printk(KERN_INFO "Текст\n");   // ✅
printk(KERN_INFO, "Текст\n");  // ❌
```

**Где смотреть вывод:**

```bash
dmesg | tail          # последние строки журнала
dmesg -w              # следить в реальном времени
dmesg -l err          # только ошибки
cat /var/log/kern.log # если есть syslog
```

⚠️ **По умолчанию на консоль выводятся только сообщения с уровнем < 4.** Чтобы увидеть `KERN_INFO`, нужно либо смотреть `dmesg`, либо изменить уровень:

```bash
echo 8 > /proc/sys/kernel/printk
```

## 5. Makefile для модуля

Модуль **нельзя собрать обычным `gcc`**. Нужна система сборки ядра.

**Минимальный Makefile:**

```makefile
obj-m += hello.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean
```

**Разбор:**

| Строка | Что означает |
|--------|--------------|
| `obj-m += hello.o` | Собрать модуль `hello.ko` из `hello.o` |
| `-C /lib/modules/.../build` | Перейти в каталог сборки ядра |
| `M=$(PWD)` | Указать, что исходники — в текущем каталоге |
| `modules` | Цель сборки — модули |

⚠️ **Перед `make` нужны заголовки ядра:**

```bash
sudo apt install linux-headers-$(uname -r)
```

**После сборки:** появится **`hello.ko`** — файл модуля.

## 6. Загрузка и выгрузка

| Команда | Что делает |
|---------|-----------|
| `sudo insmod hello.ko` | Загрузить модуль |
| `sudo rmmod hello` | Выгрузить (имя без `.ko`) |
| `lsmod \| grep hello` | Проверить, загружен ли |
| `dmesg \| tail` | Посмотреть вывод модуля |
| `modinfo hello.ko` | Информация о модуле |

**`insmod` vs `modprobe`:**

| | `insmod` | `modprobe` |
|--|:--------:|:----------:|
| Указывать путь | Нужно | Не нужно |
| Разрешать зависимости | Нет | ✅ Да |
| Искать в `/lib/modules` | Нет | ✅ Да |
| Для разработки | ✅ Удобно | Не всегда |

**Пример полного цикла:**

```bash
make                       # сборка
sudo insmod hello.ko       # загрузка
dmesg | tail               # смотрим "Hello, World!"
lsmod | grep hello         # модуль в списке
sudo rmmod hello           # выгрузка
dmesg | tail               # смотрим "Goodbye, World!"
```

## 7. Модуль с параметрами

Можно передавать параметры при загрузке:

```c
#include <linux/moduleparam.h>

static int count = 1;
static char *name = "мир";

module_param(count, int, 0644);
MODULE_PARM_DESC(count, "Сколько раз поздороваться");

module_param(name, charp, 0644);
MODULE_PARM_DESC(name, "Имя для приветствия");

static int __init hello_init(void)
{
    for (int i = 0; i < count; i++) {
        printk(KERN_INFO "Привет, %s!\n", name);
    }
    return 0;
}
```

**Загрузка с параметрами:**

```bash
sudo insmod hello.ko count=3 name="Иван"
```

**Просмотр параметров:**

```bash
ls /sys/module/hello/parameters/
cat /sys/module/hello/parameters/count
```

⚠️ Флаг `0644` — права доступа к параметру в `/sys`. `S_IRUSR | S_IWUSR | S_IRGRP | S_IROTH` = `0644`.

## 8. Версия ядра

Модуль должен быть собран **под ту же версию ядра**, на которой будет загружен. Иначе — ошибка `invalid module format` или `version magic mismatch`.

**Проверить версию:**

```bash
uname -r                    # текущая версия ядра
modinfo hello.ko            # vermagic модуля
```

**Флаги в Makefile:**

```makefile
KERNELDIR := /lib/modules/$(shell uname -r)/build
```

⚠️ Если ядро обновилось, а модуль собран под старую версию — его нужно **пересобрать**.

## 9. Что можно и нельзя в модуле

**Можно:**
- Использовать API ядра (`kmalloc`, `printk`, `register_chrdev`).
- Работать с железом.
- Обрабатывать прерывания.
- Создавать устройства, файловые системы, сетевые протоколы.

**Нельзя:**
- Использовать стандартную библиотеку C (`printf`, `malloc`, `fopen`).
- Делать долгие операции (блокируется ядро).
- Обращаться к пользовательской памяти напрямую.
- Вызывать `sleep` в атомарном контексте.

**Аналоги из ядра:**

| Пользовательское | Ядерное |
|------------------|---------|
| `printf` | `printk` |
| `malloc` / `free` | `kmalloc` / `kfree` |
| `fopen` / `fclose` | `filp_open` / `filp_close` |
| `memcpy` | `memcpy` (есть) |
| `sleep` | `msleep`, `ssleep` |

## 10. Полный пример с сообщением при загрузке

```c
#include <linux/init.h>
#include <linux/module.h>
#include <linux/kernel.h>

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Студент");
MODULE_DESCRIPTION("Пример модуля ядра");
MODULE_VERSION("1.0");

static int __init hello_init(void)
{
    printk(KERN_INFO "Модуль загружен\n");
    printk(KERN_INFO "Привет из ядра!\n");
    return 0;
}

static void __exit hello_exit(void)
{
    printk(KERN_INFO "Модуль выгружен\n");
}

module_init(hello_init);
module_exit(hello_exit);
```

**Сборка:**

```bash
make
```

**Загрузка:**

```bash
sudo insmod hello.ko
dmesg | tail -3
```

**Вывод:**

```
[12345.678] Модуль загружен
[12345.678] Привет из ядра!
```

**Выгрузка:**

```bash
sudo rmmod hello
dmesg | tail -1
```

```
[12346.789] Модуль выгружен
```

## 11. Типичные ошибки

| Ошибка | Что не так | Решение |
|--------|-----------|---------|
| `printf` в модуле | Нет стандартной библиотеки | `printk` |
| Нет `MODULE_LICENSE` | Ядро «загрязнено» | Добавить GPL |
| `insmod` без `sudo` | Нет прав | `sudo insmod` |
| Забыли `module_init` | Модуль не загрузится корректно | Добавить |
| Версия ядра не совпадает | `invalid module format` | Пересобрать |
| `rmmod` с `.ko` | Ошибка | `rmmod hello` |
| Нет заголовков ядра | `make` не работает | Установить `linux-headers` |
| Ошибка в модуле | Крах системы | Тестировать в виртуалке |

## 12. Итоги

- **Модуль ядра** — динамически загружаемый код.
- **Три обязательные части:** `module_init`, `module_exit`, `MODULE_LICENSE`.
- **`printk`** вместо `printf`; уровни `KERN_*`.
- **Makefile** для сборки `.ko`.
- **`insmod` / `rmmod`** — загрузка и выгрузка.
- **`dmesg`** — просмотр сообщений.
- **Опасно:** только в виртуальной машине.
- **Параметры** — через `module_param`.
