## 2. Проблема: гонки данных

Когда два потока одновременно обращаются к одной переменной, и хотя бы один пишет — возникает **гонка данных** (data race). Результат непредсказуем.

**Пример:**

```c
int counter = 0;

void *worker(void *arg)
{
    for (int i = 0; i < 1000000; i++) {
        counter++;   // не атомарно!
    }
    return NULL;
}
```

`counter++` — это **три операции**: прочитать, увеличить, записать. Если два потока выполнят их «одновременно», одно из приращений потеряется.

**Запустите два таких потока — и вместо `2000000` получите меньше.**

**Что нужно:** синхронизация — механизм, который **заставляет потоки ждать** друг друга, когда они лезут в общие данные.

---

## 3. Мьютекс — «замок»

**Мьютекс** (mutex — mutual exclusion) — это замок. Поток **захватывает** его перед входом в критическую секцию и **отпускает** после. Пока один поток держит мьютекс, другие **ждут**.

```c
#include <pthread.h>

pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;

pthread_mutex_lock(&lock);     // захватить
// критическая секция
pthread_mutex_unlock(&lock);   // отпустить
```

**Основные функции:**

| Функция | Что делает |
|---------|-----------|
| `pthread_mutex_init` | Инициализировать мьютекс |
| `pthread_mutex_lock` | Захватить (ждёт, если занят) |
| `pthread_mutex_trylock` | Попробовать захватить (не ждёт) |
| `pthread_mutex_unlock` | Отпустить |
| `pthread_mutex_destroy` | Уничтожить |

**Исправленный пример:**

```c
int counter = 0;
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;

void *worker(void *arg)
{
    for (int i = 0; i < 1000000; i++) {
        pthread_mutex_lock(&lock);
        counter++;
        pthread_mutex_unlock(&lock);
    }
    return NULL;
}
```

Теперь результат — **ровно 2000000**.

⚠️ **Правила:**
- Захватывайте **перед** критической секцией.
- Отпускайте **сразу после** — не держите мьютекс дольше, чем нужно.
- Нельзя захватить один и тот же мьютекс дважды (дедлок).
- `PTHREAD_MUTEX_INITIALIZER` — статическая инициализация, если мьютекс глобальный.

## 4. Условные переменные

**Мьютекс** решает проблему одновременного доступа. Но что, если поток должен **ждать события** — например, «пока в очереди не появятся данные»?

Для этого есть **условные переменные** (`pthread_cond_t`). Они позволяют потоку **заснуть** до сигнала от другого потока.

```c
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;
```

**Основные функции:**

| Функция | Что делает |
|---------|-----------|
| `pthread_cond_wait` | Ждать сигнала (отпускает мьютекс и засыпает) |
| `pthread_cond_signal` | Разбудить **один** ждущий поток |
| `pthread_cond_broadcast` | Разбудить **все** ждущие потоки |

⚠️ **`pthread_cond_wait` всегда вызывается с захваченным мьютексом.** Внутри он **отпускает** мьютекс, ждёт сигнала и **снова захватывает** перед возвратом.

**Схема:**

```
Поток-ожидающий:                    Поток-сигналящий:
lock(mutex)                         lock(mutex)
while (условие не выполнено)        изменить данные
    cond_wait(cond, mutex)          cond_signal(cond)
// условие выполнено                unlock(mutex)
unlock(mutex)
```

**Пример: очередь**

```c
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>

int queue[10];
int count = 0;
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t not_empty = PTHREAD_COND_INITIALIZER;
pthread_cond_t not_full = PTHREAD_COND_INITIALIZER;

void *producer(void *arg)
{
    for (int i = 0; i < 20; i++) {
        pthread_mutex_lock(&lock);
        while (count == 10)
            pthread_cond_wait(&not_full, &lock);

        queue[count++] = i;
        printf("Производитель: %d\n", i);

        pthread_cond_signal(&not_empty);
        pthread_mutex_unlock(&lock);
    }
    return NULL;
}

void *consumer(void *arg)
{
    for (int i = 0; i < 20; i++) {
        pthread_mutex_lock(&lock);
        while (count == 0)
            pthread_cond_wait(&not_empty, &lock);

        int value = queue[--count];
        printf("Потребитель: %d\n", value);

        pthread_cond_signal(&not_full);
        pthread_mutex_unlock(&lock);
    }
    return NULL;
}
```

⚠️ **Всегда в цикле `while`**, а не `if`. Поток может «проснуться» без реального сигнала (spurious wakeup) — нужно **перепроверить условие**.

## 5. Семафоры

**Семафор** — это счётчик, которым можно управлять атомарно. Чаще всего используется для **ограничения числа потоков**, одновременно работающих с ресурсом.

```c
#include <semaphore.h>

sem_t sem;
sem_init(&sem, 0, 5);   // 5 — начальное значение
```

**Основные функции:**

| Функция | Что делает |
|---------|-----------|
| `sem_init` | Инициализировать |
| `sem_wait` | Уменьшить счётчик; если 0 — ждать |
| `sem_post` | Увеличить счётчик; разбудить ждущих |
| `sem_destroy` | Уничтожить |
| `sem_getvalue` | Текущее значение |

**Пример: ограничение доступа**

```c
sem_t sem;

void *worker(void *arg)
{
    sem_wait(&sem);       // ждём разрешения
    // работаем с ресурсом
    printf("Поток %ld работает\n", (long)arg);
    sleep(1);
    sem_post(&sem);       // освобождаем
    return NULL;
}

int main(void)
{
    sem_init(&sem, 0, 3);   // не более 3 потоков одновременно

    pthread_t t[5];
    for (long i = 0; i < 5; i++)
        pthread_create(&t[i], NULL, worker, (void *)i);
    for (int i = 0; i < 5; i++)
        pthread_join(t[i], NULL);

    sem_destroy(&sem);
    return 0;
}
```

**Разница с мьютексом:**

| | Мьютекс | Семафор |
|--|:-------:|:-------:|
| Тип | Замок | Счётчик |
| Значение | 0/1 | 0..N |
| Кто отпускает | Тот же поток | Любой поток |
| Применение | Критическая секция | Ограничение ресурсов |

## 6. Сравнение инструментов

| Инструмент | Для чего |
|-----------|----------|
| **Мьютекс** | Защитить критическую секцию |
| **Условная переменная** | Ждать события |
| **Семафор** | Ограничить число потоков |

**Комбинация:** мьютекс + условная переменная — самая частая связка для producer-consumer.

## 7. Типичные ошибки

| Ошибка | Что не так | Решение |
|--------|-----------|---------|
| Забыли `unlock` | Дедлок | Всегда отпускать |
| `pthread_cond_wait` без мьютекса | UB | Сначала захватить |
| `if` вместо `while` вокруг `wait` | Spurious wakeup | Использовать `while` |
| `signal` вместо `broadcast` | Не разбудит всех | Выбирать осознанно |
| Забыли инициализировать | Мусор в мьютексе | `PTHREAD_*_INITIALIZER` |
| Держат мьютекс во время долгой работы | Замедление | Отпускать быстрее |
| Забыли `destroy` | Утечка ресурсов | Разрушать после использования |
| Используют семафор как мьютекс | Не то поведение | Использовать мьютекс |
| Дедлок из-за порядка захвата | Потоки ждут друг друга | Единый порядок захвата |

## 8. Итоги

- **Гонки данных** — проблема одновременного доступа.
- **Мьютекс** — защищает критическую секцию.
- **Условная переменная** — ждёт события.
- **Семафор** — ограничивает число потоков.
- **`wait` всегда в `while`**, а не `if`.
- **Не держите мьютекс дольше**, чем нужно.
- **Один порядок захвата** — против дедлоков.
