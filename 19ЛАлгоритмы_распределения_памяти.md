## 2. Зачем нужны алгоритмы распределения

Когда программа запрашивает память, ОС должна найти **свободный блок** подходящего размера. Память при этом неоднородна: одни блоки заняты, другие свободны, третьи освободились и стали «дырками».

**Проблема — фрагментация:**

| Тип | Что это |
|-----|---------|
| **Внешняя** | Свободной памяти много, но она разбита на куски, ни один из которых не подходит |
| **Внутренняя** | Блок выделен больше, чем нужно, «лишнее» пропадает |

Три классических стратегии решают, **какой именно свободный блок выбрать**.

---

## 3. First Fit (первый подходящий)

**Идея:** идём по списку свободных блоков с начала и берём **первый**, чей размер ≥ запроса.

**Алгоритм:**

1. Пройти по списку блоков.
2. Найти первый свободный блок, размер которого ≥ запроса.
3. Если блок больше запроса — **разрезать** на две части: занятую и свободную.
4. Если блок точно равен — пометить занятым.

**Пример:** запрос 212 КБ, свободные блоки: `[100, 500, 200, 300, 600]`

Первый подходящий — **500 КБ**. После выделения остаётся 288 КБ.

**Плюсы:**
- Быстро — не нужно просматривать весь список.
- Просто реализовать.

**Минусы:**
- Низкие адреса «засоряются» мелкими фрагментами.
- Крупные запросы могут не найти места в начале списка.

---

## 4. Best Fit (наиболее подходящий)

**Идея:** ищем **минимальный** свободный блок, который ещё вмещает запрос.

**Алгоритм:**

1. Пройти **весь** список.
2. Запомнить блок с наименьшим размером ≥ запроса.
3. Разрезать его, если он больше.

**Пример:** запрос 212 КБ, свободные блоки: `[100, 500, 200, 300, 600]`

Минимальный подходящий — **300 КБ**. После выделения остаётся 88 КБ.

**Плюсы:**
- Хорошо использует память.
- Оставляет большие блоки для будущих крупных запросов.

**Минусы:**
- Приходится просматривать **весь** список.
- Создаёт много **мелких** фрагментов, которые трудно использовать.

---

## 5. Worst Fit (наименее подходящий)

**Идея:** берём **самый большой** свободный блок.

**Алгоритм:**

1. Пройти весь список.
2. Найти максимальный свободный блок.
3. Выделить из него запрошенный размер, остаток оставить свободным.

**Пример:** запрос 212 КБ, свободные блоки: `[100, 500, 200, 300, 600]`

Самый большой — **600 КБ**. После выделения остаётся 388 КБ.

**Плюсы:**
- Остаток после выделения **достаточно большой**, чтобы пригодиться снова.
- Меньше мелких фрагментов в начале.

**Минусы:**
- Крупные блоки быстро **измельчаются**.
- Со временем крупные запросы уже не помещаются.
- Нужно просматривать весь список.

---

## 6. Сравнение на примере

Запрос **212 КБ**, свободные блоки `[100, 500, 200, 300, 600]`:

| Алгоритм | Выбранный блок | Остаток |
|----------|:--------------:|:-------:|
| **First Fit** | 500 КБ | 288 КБ |
| **Best Fit** | 300 КБ | 88 КБ |
| **Worst Fit** | 600 КБ | 388 КБ |

**Вывод:**
- Best Fit оставляет **минимум** «отходов».
- Worst Fit — **максимум**.
- First Fit — посередине, но **быстрее всех**.

## 8. Моделирование на C

Чтобы смоделировать алгоритмы, нужна **таблица свободных блоков**:

```c
typedef struct {
    int start;   // начальный адрес
    int size;    // размер блока
    int free;    // 1 — свободен, 0 — занят
} Block;

Block mem[100];
int n = 0;       // количество блоков
```

**Основные операции:**

1. **Поиск блока** по стратегии.
2. **Выделение:** разрезать, если блок больше запроса.
3. **Освобождение:** пометить свободным и **слить с соседями**.

### Функция поиска (First Fit)

```c
int find_first(int size)
{
    for (int i = 0; i < n; i++) {
        if (mem[i].free && mem[i].size >= size)
            return i;
    }
    return -1;
}
```

### Функция поиска (Best Fit)

```c
int find_best(int size)
{
    int idx = -1, best = 0;
    for (int i = 0; i < n; i++) {
        if (mem[i].free && mem[i].size >= size) {
            if (idx == -1 || mem[i].size < best) {
                best = mem[i].size;
                idx = i;
            }
        }
    }
    return idx;
}
```

### Функция поиска (Worst Fit)

```c
int find_worst(int size)
{
    int idx = -1, worst = 0;
    for (int i = 0; i < n; i++) {
        if (mem[i].free && mem[i].size >= size) {
            if (idx == -1 || mem[i].size > worst) {
                worst = mem[i].size;
                idx = i;
            }
        }
    }
    return idx;
}
```

## 9. Выделение памяти

```c
int allocate(int size, int strategy)
{
    int idx;
    switch (strategy) {
        case 0: idx = find_first(size); break;
        case 1: idx = find_best(size);  break;
        case 2: idx = find_worst(size); break;
        default: return -1;
    }
    if (idx == -1) return -1;

    // Разрезаем, если блок больше запроса
    if (mem[idx].size > size) {
        // Сдвигаем всё вправо
        for (int i = n; i > idx + 1; i--)
            mem[i] = mem[i - 1];
        n++;

        mem[idx + 1].start = mem[idx].start + size;
        mem[idx + 1].size  = mem[idx].size - size;
        mem[idx + 1].free  = 1;

        mem[idx].size = size;
    }
    mem[idx].free = 0;
    return mem[idx].start;
}
```

## 10. Освобождение и слияние

При освобождении важно **слить** соседние свободные блоки — иначе фрагментация только растёт.

```c
void release(int start)
{
    // Находим блок
    for (int i = 0; i < n; i++) {
        if (mem[i].start == start) {
            mem[i].free = 1;
            break;
        }
    }

    // Слияние с соседями
    for (int i = 0; i < n - 1; i++) {
        if (mem[i].free && mem[i + 1].free) {
            mem[i].size += mem[i + 1].size;
            for (int j = i + 1; j < n - 1; j++)
                mem[j] = mem[j + 1];
            n--;
            i--;
        }
    }
}
```

**Начальное состояние:** память 1000 байт, один свободный блок.

|--------|-----------|----------|-----------|
| 212 | 0–211 (из 1000) | 0–211 | 0–211 |
| 100 | след. подходящий | минимальный | максимальный |
| ... | ... | ... | ... |

**Что наблюдать:**
- Сколько свободных блоков в итоге.
- Сколько из них слишком малы для типичного запроса.
- Общая занятая память.

## 12. Что важно запомнить

1. **First Fit** — быстрый, но мусорит в начале.
2. **Best Fit** — экономит память, но оставляет мелкие фрагменты.
3. **Worst Fit** — оставляет большой остаток, но быстро измельчает крупные блоки.
4. **Слияние** при освобождении **обязательно**, иначе память исчерпается быстро.
5. **Один и тот же запрос** при разных стратегиях даёт разные результаты.

## 13. Реальные системы

Чистые First/Best/Worst Fit в современных ОС **почти не используются**. Вместо них:

| Система | Что использует |
|---------|---------------|
| Linux (ядро) | Buddy System, Slab |
| Windows | Куча с несколькими стратегиями |
| Java | Сборщик мусора |

Однако **понимание этих трёх стратегий** — база для изучения более сложных методов.
