# Лекция: Обработка ошибок в C

**Дисциплина:** Основы программирования на языке Си  
**Тема:** `errno`, `perror`, `strerror`  
**Тип занятия:** лекция (2 ч)

---

## 1. Цели и задачи

**Цель:** научиться правильно обрабатывать ошибки в программах на C: узнавать, что пошло не так, и сообщать об этом пользователю.

**Задачи:**
- Понять, зачем нужна обработка ошибок.
- Освоить `errno` — глобальную переменную с кодом ошибки.
- Освоить `perror` и `strerror` — вывод понятных сообщений.
- Разобраться, как проверять возвраты функций.

**Компетенции:** ОК 01, ОК 02, ПК 1.1, ПК 1.2.

---

## 2. Зачем обрабатывать ошибки

В C **почти ни одна функция не «падает» при ошибке** — она возвращает специальное значение:

- `-1` — для многих системных вызовов;
- `NULL` — для `fopen`, `malloc`, `opendir`;
- `EOF` — для `fgetc`;
- `0` — для успеха (в некоторых).

Если **не проверять** возврат, программа продолжит работу с «мусором» — и упадёт позже, в непредсказуемом месте. Хорошая программа **всегда проверяет** результаты операций, которые могут не удаться.

```c
FILE *f = fopen("data.txt", "r");
if (f == NULL) {
    // обработать ошибку
}
```

---

## 3. Что такое `errno`

**`errno`** — глобальная переменная, определённая в `<errno.h>`. В ней хранится **код последней ошибки**, возникшей в системном вызове или функции стандартной библиотеки.

```c
#include <errno.h>

// ... вызов функции, которая может не удаться ...
if (/* ошибка */) {
    printf("Код ошибки: %d\n", errno);
}
```

**Особенности:**

- `errno` устанавливается **только при ошибке**. При успехе её значение **не обнуляется** — там остаётся старое значение.
- Поэтому **нельзя** проверять «успешно ли прошла операция» по `errno`. Сначала проверяем **возврат**, потом смотрим `errno`.
- Разные функции устанавливают разные коды.

**Типичные константы:**

| Константа | Значение | Что означает |
|-----------|:--------:|--------------|
| `ENOENT` | 2 | Файл не найден |
| `EACCES` | 13 | Нет прав |
| `EEXIST` | 17 | Файл уже существует |
| `ENOMEM` | 12 | Нет памяти |
| `EINVAL` | 22 | Неверный аргумент |
| `EIO` | 5 | Ошибка ввода-вывода |
| `ENOSPC` | 28 | Нет места на диске |

Полный список — в `man errno`.

## 4. `strerror` — текст ошибки

```c
#include <string.h>

char *strerror(int errnum);
```

**Что делает:** возвращает **строку** с описанием ошибки по коду.

**Пример:**

```c
#include <stdio.h>
#include <string.h>
#include <errno.h>

FILE *f = fopen("missing.txt", "r");
if (f == NULL) {
    printf("Ошибка: %s\n", strerror(errno));
    // выведет: Ошибка: No such file or directory
}
```

**Особенности:**
- Строка — **статическая**, её не нужно освобождать.
- Описание — на **английском** (зависит от локали).
- `strerror` **не потокобезопасна** — используйте `strerror_r`, если работаете с потоками.

---

## 5. `perror` — короткий вывод

```c
#include <stdio.h>

void perror(const char *s);
```

**Что делает:** выводит в `stderr` строку `<префикс>: <описание ошибки>\n`.

**Пример:**

```c
FILE *f = fopen("missing.txt", "r");
if (f == NULL) {
    perror("fopen");
    // выведет: fopen: No such file or directory
}
```

**Особенности:**
- Работает как `fprintf(stderr, "%s: %s\n", s, strerror(errno))`.
- Если `s == NULL` или `""` — выводит только описание.
- `perror` — самый короткий способ сообщить об ошибке.

---

## 6. `strerror` vs `perror`

| Способ | Код | Вывод |
|--------|-----|-------|
| `perror` | `perror("fopen");` | `fopen: No such file or directory` |
| `strerror` | `printf("Ошибка: %s\n", strerror(errno));` | `Ошибка: No such file or directory` |
| `fprintf` + `strerror` | `fprintf(stderr, "Ошибка: %s\n", strerror(errno));` | `Ошибка: No such file or directory` |

**Разница:**
- `perror` — **короче**.
- `strerror` — **гибче**: можно вставить в любое место вывода, в том числе в свои сообщения.

## 7. Полный пример

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <fcntl.h>
#include <unistd.h>

int main(void)
{
    // 1. fopen
    FILE *f = fopen("no_such_file.txt", "r");
    if (f == NULL) {
        perror("fopen");
    }

    // 2. open
    int fd = open("no_such_file.txt", O_RDONLY);
    if (fd == -1) {
        fprintf(stderr, "open: %s\n", strerror(errno));
    }

    // 3. malloc
    void *p = malloc(10000000000000);
    if (p == NULL) {
        perror("malloc");
    }

    // 4. chdir
    if (chdir("/no/such/dir") == -1) {
        perror("chdir");
    }

    return 0;
}
```

**Возможный вывод:**

```
fopen: No such file or directory
open: No such file or directory
malloc: Cannot allocate memory
chdir: No such file or directory
```

## 8. Как правильно проверять

**Плохо:**

```c
FILE *f = fopen("file.txt", "r");
if (errno != 0) {          // ❌ errno может быть старым
    perror("fopen");
}
```

**Хорошо:**

```c
FILE *f = fopen("file.txt", "r");
if (f == NULL) {           // ✅ сначала проверяем возврат
    perror("fopen");
}
```

**Правило:** сначала проверяем **возврат функции**, и **только если он сигналит об ошибке** — обращаемся к `errno`.

---

## 9. Своя функция для вывода

Иногда удобно обернуть `perror` в свою функцию:

```c
#include <stdio.h>
#include <string.h>
#include <errno.h>

void die(const char *msg)
{
    fprintf(stderr, "Ошибка: %s: %s\n", msg, strerror(errno));
    exit(1);
}

// Использование:
FILE *f = fopen("file.txt", "r");
if (f == NULL) die("fopen");
```

---

## 10. Потокобезопасность

`errno` — **потокобезопасна** в POSIX (у каждого потока своя копия), но `strerror` — **нет**: она возвращает указатель на статический буфер.

**Безопасный вариант:**

```c
char buf[256];
strerror_r(errno, buf, sizeof(buf));
printf("Ошибка: %s\n", buf);
```

⚠️ `strerror_r` имеет **две версии** — GNU и POSIX. Поведение может отличаться.

## 11. Связь с системными вызовами

**Системные вызовы** (`open`, `read`, `write`, `fork`, `chdir`, `stat`) при ошибке:

- возвращают `-1`,
- **и** устанавливают `errno`.

**Библиотечные функции** (`fopen`, `malloc`, `opendir`) при ошибке:

- возвращают `NULL`,
- **и** тоже устанавливают `errno`.

**Функции, которые не используют `errno`:**

- `atoi`, `atof` — не сигналят об ошибке.
- `strlen` — не может ошибиться.
- `printf` — обычно не проверяют.

## 12. Типичные ошибки

| Ошибка | Что не так | Решение |
|--------|-----------|---------|
| Проверять `errno` без проверки возврата | `errno` может быть старым | Сначала `if (f == NULL)` |
| Обнулять `errno` перед вызовом | Не обязательно, но полезно | `errno = 0;` — если нужно |
| Игнорировать `-1` | Программа падает позже | Всегда проверять |
| Использовать `strerror` в потоках | Не потокобезопасна | `strerror_r` |
| Забыть `perror`/`strerror` | Непонятно, что произошло | Выводить описание |
| Выводить `errno` как число | Непонятно пользователю | Использовать `strerror` |
| `printf` вместо `fprintf(stderr, ...)` | Ошибки должны идти в `stderr` | Использовать `stderr` |

---

## 13. Итоги

- **`errno`** — глобальная переменная с кодом последней ошибки.
- **Устанавливается только при ошибке**, поэтому сначала проверяем **возврат**.
- **`strerror`** — текстовая расшифровка кода.
- **`perror`** — короткий вывод в `stderr`.
- **Системные вызовы** возвращают `-1`, **библиотечные** — `NULL`.
- **Ошибки** выводят в `stderr`, а не в `stdout`.
- **В потоках** используйте `strerror_r`.
