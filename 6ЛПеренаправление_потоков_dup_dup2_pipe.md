**Цель:** разобраться, как в Linux перенаправлять потоки ввода-вывода между процессами и файлами, используя системные вызовы `dup`, `dup2` и `pipe`.

## 2. Что такое дескриптор

**Файловый дескриптор** — это целое неотрицательное число, которым операционная система обозначает открытый файл, канал или устройство.

Когда программа открывает файл через `open`, ядро выделяет **наименьший свободный** дескриптор. По умолчанию три дескриптора уже заняты:

| Дескриптор | Имя | Что это |
|:----------:|-----|---------|
| 0 | `stdin` | Стандартный ввод |
| 1 | `stdout` | Стандартный вывод |
| 2 | `stderr` | Стандартный вывод ошибок |

Когда вы пишете `printf(...)`, данные **фактически** уходят в дескриптор 1. Когда читаете через `scanf`, читается из дескриптора 0. А `perror` пишет в дескриптор 2.

**Идея перенаправления:** можно **подменить** дескриптор — сделать так, чтобы номер 1 указывал не на терминал, а на файл. Тогда всё, что пишется в `stdout`, попадёт в файл.

---

## 3. Системный вызов `dup`

```c
#include <unistd.h>

int dup(int oldfd);
```

**Что делает:** создаёт **копию** дескриптора `oldfd` и возвращает **новый** дескриптор — наименьший свободный.

**Важно:** оба дескриптора указывают на **одну и ту же** открытую файловую структуру. Если один смещает позицию чтения/записи, второй это «видит».

**Пример:**

```c
int fd = open("data.txt", O_RDONLY);   // fd = 3
int copy = dup(fd);                    // copy = 4 — тот же файл
```

**Зачем это нужно:**
- Сохранить «старый» дескриптор, прежде чем подменить его.
- Организовать несколько независимых «входов» в один и тот же файл.

---

## 4. Системный вызов `dup2`

```c
int dup2(int oldfd, int newfd);
```

**Что делает:** делает `newfd` копией `oldfd`. Если `newfd` уже был открыт — **закрывает его**.

**Возвращает:** `newfd` при успехе, `-1` при ошибке.

**Пример:**

```c
int fd = open("output.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
dup2(fd, 1);   // теперь stdout (дескриптор 1) — это output.txt
close(fd);     // fd больше не нужен, но дескриптор 1 остался

printf("Это попадёт в файл, а не на экран\n");
```

Именно так работают перенаправления в shell:

```bash
ls > output.txt
```

Shell:
1. Открывает файл `output.txt` → получает дескриптор, например 3.
2. Делает `dup2(3, 1)` — теперь stdout = файл.
3. Запускает `ls` — она пишет в stdout, а он теперь указывает в файл.

**Разница между `dup` и `dup2`:**

| | `dup` | `dup2` |
|--|-------|--------|
| Куда копирует | Наименьший свободный | В указанный `newfd` |
| Старый дескриптор | Не трогает | Закрывает, если был открыт |
| Типичное применение | Сохранить ссылку | Подменить stdout/stdin |

## 5. Восстановление дескриптора

Чтобы вернуть `stdout` на место, сохраняют копию заранее:

```c
int saved = dup(1);            // сохраняем текущий stdout

int fd = open("log.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
dup2(fd, 1);                   // перенаправляем в файл
close(fd);

printf("Это в файле\n");

fflush(stdout);                // сбрасываем буфер!
dup2(saved, 1);                // возвращаем stdout
close(saved);

printf("Это снова на экране\n");
```

⚠️ **Обязательно `fflush(stdout)`** перед восстановлением — иначе буфер может «уйти» не туда.

## 6. Каналы (`pipe`)

**`pipe`** создаёт **однонаправленный канал** для передачи данных между процессами.

```c
#include <unistd.h>

int pipe(int pipefd[2]);
```

**Что делает:** создаёт два дескриптора:
- `pipefd[0]` — **читающий** конец.
- `pipefd[1]` — **пишущий** конец.

**Возвращает:** `0` при успехе, `-1` при ошибке.

**Схема:**

```
Писатель → pipefd[1] ═══════► pipefd[0] → Читатель
             (запись)          (чтение)
```

⚠️ **Канал однонаправленный.** Для двустороннего обмена нужно **два** канала.

---

## 7. Использование `pipe`

### Пример 1. Один процесс

```c
#include <unistd.h>
#include <stdio.h>
#include <string.h>

int main(void)
{
    int fd[2];
    if (pipe(fd) == -1) {
        perror("pipe");
        return 1;
    }

    const char *msg = "Hello, pipe!";
    write(fd[1], msg, strlen(msg));
    close(fd[1]);      // закрываем пишущий конец

    char buf[100];
    ssize_t n = read(fd[0], buf, sizeof(buf) - 1);
    if (n > 0) {
        buf[n] = '\0';
        printf("Прочитано: %s\n", buf);
    }
    close(fd[0]);
    return 0;
}
```

### Пример 2. Между процессами через `fork`

```c
#include <unistd.h>
#include <stdio.h>
#include <string.h>
#include <sys/wait.h>

int main(void)
{
    int fd[2];
    if (pipe(fd) == -1) { perror("pipe"); return 1; }

    pid_t pid = fork();
    if (pid == 0) {
        // Ребёнок — писатель
        close(fd[0]);                     // закрываем чтение
        const char *msg = "От ребёнка";
        write(fd[1], msg, strlen(msg));
        close(fd[1]);
    } else {
        // Родитель — читатель
        close(fd[1]);                     // закрываем запись
        char buf[100];
        ssize_t n = read(fd[0], buf, sizeof(buf) - 1);
        if (n > 0) {
            buf[n] = '\0';
            printf("Родитель получил: %s\n", buf);
        }
        close(fd[0]);
        wait(NULL);
    }
    return 0;
}
```

⚠️ **Правило:** в каждом процессе закрывайте **ненужный конец**. Иначе чтение может «зависнуть», потому что писатель всё ещё открыт.

## 8. Связка `pipe` + `dup2`

Классический приём: перенаправить stdout одной программы в stdin другой.

```c
int fd[2];
pipe(fd);

pid_t pid = fork();
if (pid == 0) {
    // Ребёнок: пишем в pipe
    close(fd[0]);
    dup2(fd[1], 1);      // stdout → pipe
    close(fd[1]);
    execlp("ls", "ls", NULL);
} else {
    // Родитель: читаем из pipe
    close(fd[1]);
    dup2(fd[0], 0);      // stdin ← pipe
    close(fd[0]);
    execlp("wc", "wc", "-l", NULL);
}
```

Это **точно то, что делает shell** при выполнении:

```bash
ls | wc -l
```

---

## 9. Как это выглядит в shell

| Команда | Что делает | Реализация |
|---------|-----------|-----------|
| `ls > file` | stdout в файл | `open` + `dup2` |
| `wc < file` | stdin из файла | `open` + `dup2` |
| `ls \| wc` | stdout первого в stdin второго | `pipe` + `fork` + `dup2` |
| `ls > file 2>&1` | stdout и stderr в файл | `dup2` дважды |

Понимание `dup`, `dup2`, `pipe` — ключ к пониманию того, как устроена командная строка Linux.

---

## 10. Закрытие дескрипторов

**Правило:** закрывайте всё, что открыли, и всё, что больше не нужно.

- После `dup2` **исходный дескриптор можно закрыть** — копия уже существует.
- В `pipe` **закрывайте ненужный конец** — иначе возможны зависания.
- При `fork` **родитель и ребёнок** должны закрывать «чужие» концы канала.

⚠️ **Утечка дескрипторов** — серьёзная проблема. У каждого процесса есть лимит (обычно 1024), после чего `open` и `pipe` начнут возвращать ошибки.

---

## 11. Типичные ошибки

| Ошибка | Что не так |
|--------|-----------|
| Забыли `fflush` перед `dup2` | Буфер уйдёт не туда |
| Не закрыли `fd` после `dup2` | Утечка дескриптора |
| Оставили открытыми оба конца `pipe` | Чтение зависнет |
| Забыли проверить `-1` | Работа с невалидным дескриптором |
| `dup2` без сохранения старого | Нельзя восстановить |
| Игнорирование ошибок `read`/`write` | Потеря данных |
| `pipe` в одном процессе без `fork` | Смысла почти нет |

---

## 12. Итоги

- **Дескриптор** — целое число, обозначающее открытый файл.
- **`dup`** — копирует дескриптор в наименьший свободный.
- **`dup2`** — копирует в указанный, закрывая старый.
- **`pipe`** — создаёт канал между двумя концами.
- **Перенаправление** = `open` + `dup2`.
- **Конвейер** = `pipe` + `fork` + `dup2` в каждом процессе.
- **Всегда закрывайте** дескрипторы и сбрасывайте буфер.
