## 2. Что такое `exec`

**`exec`** — это семейство функций, которые **заменяют текущий процесс** новой программой.

Когда `exec` вызывается:
1. Текущий код **прекращает** выполняться.
2. Адресное пространство **заменяется** на новое.
3. Управление **передаётся** новой программе.
4. **PID остаётся тем же** — процесс тот же, но программа другая.

⚠️ **`exec` не создаёт новый процесс.** Он **заменяет** текущий. Если `exec` успешен — управление **никогда** не вернётся в исходный код.

**Схема:**

```
До exec:
    Процесс PID 1234 → программа A

После exec:
    Процесс PID 1234 → программа B
```

---

## 3. Семейство `exec*`

Всего **шесть** функций:

| Функция | Аргументы | Поиск | Окружение |
|---------|-----------|-------|-----------|
| `execl` | Список | Полный путь | Текущее |
| `execlp` | Список | По `PATH` | Текущее |
| `execle` | Список | Полный путь | Своё |
| `execv` | Массив | Полный путь | Текущее |
| `execvp` | Массив | По `PATH` | Текущее |
| `execvpe` | Массив | По `PATH` | Своё |

**Суффиксы:**
- **`l`** (list) — аргументы перечисляются как список.
- **`v`** (vector) — аргументы в массиве.
- **`p`** (path) — искать программу в `PATH`.
- **`e`** (environment) — передать своё окружение.

---

## 4. `execl` — список аргументов

```c
#include <unistd.h>

int execl(const char *path, const char *arg, ...);
```

**Параметры:**
- `path` — **полный путь** к программе.
- `arg...` — аргументы, **завершающиеся `NULL`**.
- Первый аргумент — обычно **имя программы**.

**Пример:**

```c
#include <unistd.h>
#include <stdio.h>

int main(void)
{
    printf("До exec\n");

    execl("/bin/ls", "ls", "-l", NULL);

    // Сюда попадём, только если exec не сработал
    perror("execl");
    return 1;
}
```

**Вывод:** сначала «До exec», затем — вывод `ls -l`. Программа `main` **не вернётся**.

⚠️ **`NULL` в конце обязателен** — иначе `exec` будет читать мусор из стека.

---

## 5. `execlp` — поиск в `PATH`

```c
int execlp(const char *file, const char *arg, ...);
```

**Отличие:** не нужен полный путь — программа ищется в `PATH`.

**Пример:**

```c
execlp("ls", "ls", "-l", NULL);
execlp("gcc", "gcc", "--version", NULL);
```

⚠️ **Первый аргумент — имя программы**, второй — снова имя (как `argv[0]`). Это не опечатка, а исторически сложившееся соглашение.

---

## 6. `execv` — массив аргументов

```c
int execv(const char *path, char *const argv[]);
```

**Параметры:**
- `path` — полный путь.
- `argv` — массив строк, **заканчивающийся `NULL`**.

**Пример:**

```c
char *args[] = { "ls", "-l", "-a", NULL };
execv("/bin/ls", args);
```

**Когда использовать:** когда число аргументов **неизвестно** заранее.

---

## 7. `execvp` — массив + `PATH`

```c
int execvp(const char *file, char *const argv[]);
```

**Отличие:** ищет программу в `PATH`.

**Пример:**

```c
char *args[] = { "gcc", "main.c", "-o", "app", NULL };
execvp("gcc", args);
```

**Это самая удобная функция** для запуска стандартных программ.

---

## 8. `execle` — своё окружение

```c
int execle(const char *path, const char *arg, ..., char *const envp[]);
```

**Отличие:** последним аргументом передаётся **массив переменных окружения**.

**Пример:**

```c
char *env[] = { "PATH=/bin:/usr/bin", "HOME=/tmp", NULL };
execle("/bin/ls", "ls", "-l", NULL, env);
```

**Когда использовать:** когда нужно **изолированное окружение** (например, для тестов).

## 9. Как работает `fork` + `exec`

**`exec` заменяет процесс**, поэтому его **нельзя** использовать как «запуск программы рядом». Чтобы запустить программу и продолжить работу, нужен `fork`:

```
fork → в ребёнке exec → родитель продолжает работу
```

**Схема:**

```
Родитель ─── fork ───┬── Ребёнок ── exec ──→ Новая программа
                     │
                     └── Продолжает работу
```

**Пример:**

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void)
{
    pid_t pid = fork();

    if (pid == 0) {
        // Ребёнок: запускаем ls
        execlp("ls", "ls", "-l", NULL);

        // Если exec не сработал
        perror("execlp");
        _exit(1);
    }

    // Родитель: ждёт ребёнка
    int status;
    waitpid(pid, &status, 0);

    printf("ls завершился с кодом %d\n", WEXITSTATUS(status));
    return 0;
}
```

⚠️ **В ребёнке после `exec` нельзя использовать `exit`** — нужно `_exit` (из `<unistd.h>`), потому что `exit` может сбросить буферы, которые уже «унаследованы» от родителя. `_exit` завершает процесс немедленно.

## 10. Что наследуется при `exec`

| Что | Наследуется? |
|-----|:-----------:|
| PID | ✅ |
| PPID | ✅ |
| Открытые дескрипторы | ✅ (кроме `FD_CLOEXEC`) |
| Текущий каталог | ✅ |
| Переменные окружения | ✅ (если не переопределены) |
| Маски прав (`umask`) | ✅ |
| Сигналы | ✅ (сбрасываются некоторые) |
| **Переменные программы** | ❌ (память заменяется) |
| **Код программы** | ❌ |

⚠️ **Дескрипторы наследуются.** Если нужно, чтобы после `exec` дескриптор закрылся, установите флаг `FD_CLOEXEC` через `fcntl`.

---

## 11. Что происходит при ошибке

Если `exec` **не удался** (программа не найдена, нет прав), функция возвращает `-1` и устанавливает `errno`. Код **продолжает выполняться** со следующей строки.

**Пример:**

```c
execl("/no/such/program", "prog", NULL);
perror("execl");   // выведет: execl: No such file or directory
return 1;
```

⚠️ **Всегда проверяйте возврат `exec`** — если программа не запустится, нужно сообщить об ошибке и корректно завершиться.

## 12. Полезные примеры

### Запуск `ls -l`

```c
execlp("ls", "ls", "-l", NULL);
```

### Запуск `gcc` для компиляции

```c
char *args[] = { "gcc", "main.c", "-o", "app", NULL };
execvp("gcc", args);
```

### Запуск собственного скрипта

```c
execl("./script.sh", "script.sh", "arg1", "arg2", NULL);
```

### Замена текущей программы

```c
execvp("bash", (char *[]){ "bash", NULL });
```

### Использование `exec` без `fork`

Если программа должна **замениться** другой (например, обёртка), `fork` не нужен:

```c
int main(int argc, char *argv[])
{
    if (argc < 2) {
        fprintf(stderr, "Использование: %s <программа>\n", argv[0]);
        return 1;
    }
    execvp(argv[1], &argv[1]);
    perror("execvp");
    return 1;
}
```

Это классическая **обёртка** — например, `time`, `nice`, `env`.

## 13. `exec` и shell

Когда вы вводите команду в shell:
1. Shell вызывает `fork`.
2. Ребёнок вызывает `execvp` с командой.
3. Shell (родитель) ждёт завершения через `waitpid`.

Так работает **каждая** команда, которую вы вводите в терминале.

**Конвейер `ls | wc -l`:**
1. Создаётся `pipe`.
2. Два `fork`.
3. В первом ребёнке `dup2` и `execvp("ls")`.
4. Во втором ребёнке `dup2` и `execvp("wc")`.
5. Родитель ждёт обоих.

## 14. Типичные ошибки

| Ошибка | Что не так | Решение |
|--------|-----------|---------|
| Забыли `NULL` в конце | UB — exec читает мусор | Всегда завершать `NULL` |
| Использование `exit` в ребёнке после `exec` | Буферы сбросятся дважды | Использовать `_exit` |
| Не проверяют возврат `exec` | Ошибка останется незамеченной | Проверять `-1` |
| `execl` без полного пути | Программа не найдётся | `execlp` или полный путь |
| Не вызывают `wait` | Зомби | Всегда ждать |
| Забыли закрыть дескрипторы | Утечка | Закрывать ненужные |
| Первый аргумент — не имя программы | Программа получит странный `argv[0]` | Передавать имя |
| Использование `exec` без `fork` для «запуска рядом» | Процесс заменится | Нужен `fork` |

## 15. Итоги

- **`exec`** заменяет текущий процесс новой программой.
- **`l`** — список аргументов, **`v`** — массив.
- **`p`** — искать в `PATH`, **`e`** — своё окружение.
- **`execlp`** и **`execvp`** — самые удобные для запуска стандартных программ.
- **`fork` + `exec`** — основа запуска программ в Unix.
- **После `exec`** код не возвращается — проверяйте `-1`.
- **В ребёнке** используйте `_exit`, а не `exit`.
