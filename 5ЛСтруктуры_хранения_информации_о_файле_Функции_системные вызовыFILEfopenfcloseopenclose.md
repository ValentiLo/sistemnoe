## 1. Цели и задачи

**Цель:** разобраться, как в C устроена работа с файлами на двух уровнях — высокоуровневом (через `FILE`) и низкоуровневом (через системные вызовы).

**Задачи:**
- Понять, что такое поток и структура `FILE`.
- Освоить `fopen`/`fclose` — высокоуровневый ввод-вывод.
- Освоить `open`/`close` — системные вызовы POSIX.
- Увидеть разницу между буферизованным и небуферизованным вводом-выводом.

**Компетенции:** ОК 01, ОК 02, ПК 1.1, ПК 1.2.

## 2. Два уровня работы с файлами

В C есть **два способа** работы с файлами, и они не взаимоисключающие:

| Уровень | Функции | Что использует | Где объявлено |
|---------|---------|----------------|---------------|
| **Высокий (буферизованный)** | `fopen`, `fclose`, `fread`, `fwrite`, `fprintf`, `fscanf` | `FILE *` | `<stdio.h>` |
| **Низкий (системные вызовы)** | `open`, `close`, `read`, `write`, `lseek` | файловый дескриптор (`int`) | `<fcntl.h>`, `<unistd.h>` |

Первый — **стандарт C**, работает везде.  
Второй — **POSIX**, работает в Linux и Unix-системах.

Первый **построен поверх** второго: когда вы вызываете `fopen`, внутри происходит системный вызов `open`. Но между ними есть **буфер**, который оптимизирует работу.

## 3. Поток и структура FILE

Когда вы открываете файл через `fopen`, вы получаете **поток** — абстракцию, через которую идёт обмен данными.

**`FILE`** — это структура, определённая в `<stdio.h>`. Внутри неё хранится:

| Поле | Что содержит |
|------|--------------|
| Файловый дескриптор | Номер, который ОС выдала файлу |
| Буфер | Область памяти для накопления данных |
| Позиция | Текущее место чтения/записи |
| Режим | Чтение, запись, добавление |
| Флаги ошибок | `EOF`, ошибки |
| Счётчики | Сколько байт прочитано/записано |

Мы **не работаем** с полями `FILE` напрямую — только через функции. Сама структура скрыта от нас.

**Три стандартных потока** открыты всегда:

| Поток | Что это | Дескриптор |
|-------|---------|:----------:|
| `stdin` | Стандартный ввод | 0 |
| `stdout` | Стандартный вывод | 1 |
| `stderr` | Стандартный вывод ошибок | 2 |

Их не нужно открывать или закрывать — они уже готовы.

## 4. fopen — открыть файл

```c
#include <stdio.h>

FILE *fopen(const char *filename, const char *mode);
```

**Параметры:**
- `filename` — имя файла (путь).
- `mode` — режим открытия.

**Возвращает:** указатель на `FILE` или `NULL` при ошибке.

**Режимы:**

| Режим | Что делает |
|-------|-----------|
| `"r"` | Чтение (файл должен существовать) |
| `"w"` | Запись (создаёт или очищает) |
| `"a"` | Дозапись в конец |
| `"r+"` | Чтение и запись |
| `"w+"` | Чтение и запись (очищает) |
| `"a+"` | Чтение и дозапись |
| `"rb"`, `"wb"`, `"ab"` | Бинарные режимы |

**Пример:**

```c
FILE *f = fopen("data.txt", "r");
if (f == NULL) {
    perror("fopen");
    return 1;
}
```

**Проверка `NULL` обязательна** — иначе при отсутствии файла программа упадёт.

## 5. fclose — закрыть файл

```c
int fclose(FILE *stream);
```

**Что делает:**
1. Сбрасывает **буфер** на диск.
2. Закрывает файловый дескриптор.
3. Освобождает ресурсы.

**Возвращает:** `0` при успехе, `EOF` при ошибке.

**Пример:**

```c
fclose(f);
f = NULL;
```

⚠️ **Не закрыть файл — плохо:**
- Данные из буфера могут не попасть на диск.
- Дескриптор останется занятым (в Linux их ограниченное число).
- Другие программы не смогут открыть файл.

⚠️ **Двойное закрытие** — UB, может привести к крашу.

## 6. Системные вызовы open/close

Эти функции работают **на уровне ОС**, без буфера. Они возвращают **файловый дескриптор** — целое число.

### open

```c
#include <fcntl.h>
#include <unistd.h>

int open(const char *pathname, int flags);
int open(const char *pathname, int flags, mode_t mode);
```

**Флаги:**

| Флаг | Что означает |
|------|--------------|
| `O_RDONLY` | Только чтение |
| `O_WRONLY` | Только запись |
| `O_RDWR` | Чтение и запись |
| `O_CREAT` | Создать, если нет |
| `O_TRUNC` | Очистить файл |
| `O_APPEND` | Дозапись в конец |

**Возвращает:** дескриптор (≥ 0) или `-1` при ошибке.

**Пример:**

```c
int fd = open("data.txt", O_RDONLY);
if (fd == -1) {
    perror("open");
    return 1;
}
```

**Создание файла:**

```c
int fd = open("new.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
```

`0644` — права доступа: владелец читает/пишет, остальные — только читают.

### close

```c
int close(int fd);
```

**Возвращает:** `0` при успехе, `-1` при ошибке.

**Пример:**

```c
close(fd);
```

## 7. Сравнение двух подходов

| Критерий | `FILE *` (fopen) | Дескриптор (open) |
|----------|------------------|-------------------|
| Уровень | Высокий | Низкий |
| Буферизация | ✅ Есть | ❌ Нет |
| Скорость мелких операций | Быстрее (буфер) | Медленнее |
| Контроль | Меньше | Полный |
| Переносимость | Везде | Только POSIX |
| Возвращает | `FILE *` | `int` |
| Заголовок | `<stdio.h>` | `<fcntl.h>`, `<unistd.h>` |

**Когда что использовать:**

- **`fopen`** — почти всегда. Особенно для текста, построчной обработки, форматированного ввода-вывода.
- **`open`** — когда нужен **точный контроль**: небуферизованный ввод-вывод, работа с устройствами, специфические флаги (`O_NONBLOCK`, `O_DIRECT`), низкоуровневые операции.

## 8. Что происходит при открытии

Упрощённо, `fopen` делает так:

1. Вызывает `open` — получает файловый дескриптор.
2. Выделяет структуру `FILE`.
3. Выделяет буфер (обычно 4–8 КБ).
4. Заполняет поля структуры.
5. Возвращает указатель на `FILE`.

При `fclose`:

1. Сбрасывает буфер (`fflush`).
2. Вызывает `close`.
3. Освобождает структуру `FILE` и буфер.

Поэтому **`fopen`/`fclose` дороже**, чем `open`/`close` — но зато работают быстрее за счёт буфера.

## 9. Пример: чтение файла двумя способами

### Через fopen

```c
#include <stdio.h>

int main(void)
{
    FILE *f = fopen("data.txt", "r");
    if (f == NULL) {
        perror("fopen");
        return 1;
    }

    int c;
    while ((c = fgetc(f)) != EOF) {
        putchar(c);
    }

    fclose(f);
    return 0;
}
```

### Через open

```c
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main(void)
{
    int fd = open("data.txt", O_RDONLY);
    if (fd == -1) {
        perror("open");
        return 1;
    }

    char buf[1024];
    ssize_t n;
    while ((n = read(fd, buf, sizeof(buf))) > 0) {
        write(STDOUT_FILENO, buf, n);
    }

    close(fd);
    return 0;
}
```

Оба делают одно и то же, но первый — **проще** и **быстрее** для мелких операций.

## 10. Метаданные файла

Информация о файле (размер, права, время изменения) хранится в **inode** — структуре файловой системы. Получить её можно через:

- **`stat`**, **`fstat`**, **`lstat`** — системные вызовы.
- Через `FILE *` — с помощью `fileno(f)` получить дескриптор и затем `fstat`.

**Пример:**

```c
#include <sys/stat.h>
#include <stdio.h>

struct stat st;
if (stat("data.txt", &st) == 0) {
    printf("Размер: %ld байт\n", st.st_size);
    printf("Права: %o\n", st.st_mode & 0777);
}
```

## 11. Типичные ошибки

| Ошибка | Что не так |
|--------|-----------|
| Нет проверки `f == NULL` | Краш при отсутствии файла |
| Забыли `fclose` | Утечка дескриптора, данные не сохраняются |
| Двойное `fclose` | UB, краш |
| `open` без `O_CREAT` для нового файла | `-1` (файл не существует) |
| Неправильный режим `"r"` для записи | Ошибка |
| `open` без проверки `fd == -1` | Работа с невалидным дескриптором |
| Забыли `close` | Утечка дескрипторов |
| Использование `FILE *` после `fclose` | Мусор |

## 12. Итоги

- **Два уровня:** `FILE *` (высокий) и дескриптор (низкий).
- **`fopen`/`fclose`** — высокоуровневые, с буфером.
- **`open`/`close`** — системные вызовы, без буфера.
- **`FILE`** — структура, содержащая дескриптор, буфер, позицию, флаги.
- **Всегда проверяйте** на `NULL` (для `FILE`) и `-1` (для дескриптора).
- **Закрывайте** файлы — это освобождает ресурсы.
- **Для обычной работы** — `fopen`. **Для контроля** — `open`.
